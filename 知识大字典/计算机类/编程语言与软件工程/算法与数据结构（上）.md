## 序：基本概念<a id = "序"></a>
### 0.1 算法定义与性质<a id = "0.1"></a>

在深入学习具体的数据结构和算法之前，必须明确“算法”本身是什么。本节从数学和计算机科学的角度，给出算法的严格定义，剖析其五大核心性质，并厘清算法与程序这两个极易混淆的概念。

#### 一、算法的定义

**算法（Algorithm）** 是对特定问题求解步骤的一种准确而完整的描述，是一个由若干条指令组成的有穷序列。它接收一组输入（或不接收），经过有限的计算步骤，产生一个或多个输出。

从数学角度看，算法是一个从输入域到输出域的映射关系，其计算过程可以用图灵机等计算模型严格定义。通俗地说，算法就是解决一个问题所遵循的清晰指令集合。

#### 二、算法的五大基本性质

一个有效的算法必须满足以下五个基本性质（特性），缺一不可：

##### 1. 输入（Input）
- **定义**：算法可以具有**零个或多个**外部输入，这些输入是算法开始前给定的初始数据。
- **说明**：输入可以是用户提供的数据，也可以是程序内部预设的参数。有些算法（如返回固定常数的算法）可以没有输入，但大多数算法需要输入来驱动其逻辑。

##### 2. 输出（Output）
- **定义**：算法必须具有**至少一个**输出。
- **说明**：输出是算法处理后产生的结果，用于表达问题的答案或加工后的数据。没有输出的算法是毫无意义的，因为我们无法知道它解决了什么问题。

##### 3. 确定性（Definiteness / Unambiguity）
- **定义**：算法中的每一条指令都必须是明确的、无歧义的。
- **说明**：在任何条件下，算法执行的下一步都必须是确定的。例如，“将 a 与 b 相加”是明确的；而“取一个足够大的数”或“随机选择一个数”如果未限定随机策略，则违反了确定性（除非有明确的随机种子策略，但这也属于确定性描述）。
- **注意**：随机化算法虽有随机数参与，但每一步的概率分布和操作逻辑依然是明确界定的。

##### 4. 有限性（Finiteness）
- **定义**：算法必须在执行**有限步**之后终止。
- **说明**：算法不能包含无限循环或无限递归（除非是死循环程序，但那不是算法）。无论输入规模如何，算法都必须在有限的时间内给出结果。
- **例**：计算 1 到 100 的和的算法必须在 100 次加法后结束。

##### 5. 可行性（Effectiveness / Feasibility）
- **定义**：算法中的每一步操作都必须是**可行的**，即能够通过已经实现的基本运算在有限时间内完成。
- **说明**：算法不能依赖于人类无法执行或理论上无法实现的魔法操作（如“求出方程的精确解”如果无法用基本四则运算实现，则不可行）。每一条指令都必须是足够简单、可被计算机或执行者实际执行的。

#### 三、算法与程序的区别

“算法”和“程序”是两个关联紧密但截然不同的概念。以下是它们的核心区别：

| 比较维度 | **算法 (Algorithm)** | **程序 (Program)** |
| :--- | :--- | :--- |
| **本质属性** | 逻辑抽象、方法学描述 | 具体实现、物理实体 |
| **语言依赖** | 不依赖于特定的编程语言 | 必须使用特定的编程语言编码 |
| **平台依赖** | 独立于操作系统和硬件 | 依赖于特定的运行环境（如操作系统、CPU架构） |
| **有限性要求** | **必须**满足有限性（必须在有限步结束） | **可以**不满足有限性（如操作系统、服务器循环） |
| **粒度** | 侧重于宏观的步骤和逻辑流程 | 侧重于微观的语法、变量声明、内存分配 |
| **存在形式** | 可以用自然语言、伪代码或流程图描述 | 必须是源文件（.c, .java, .py 等）或可执行文件 |

**经典误区**：一个正确的算法必须在有限步内终止。然而，一个正在运行的操作系统进程（如 Windows 内核）在用户关机前会一直处于死循环状态，它不满足“有限性”，因此我们称它为“程序”或“进程”，而不是一个“算法”（或者说它内部由无数个有穷的算法子程序驱动）。

#### 四、总结与引申

掌握算法的定义和性质是学习数据结构的第一步：

1. **判定标准**：在面对一个解题思路时，先用“确定性”和“可行性”检查其是否严谨，再用“有限性”判断其是否可行。无穷循环或模糊不清的步骤都不是合法的算法。
2. **学习意义**：后续学习的所有排序、查找、图论算法，都是本节定义的具体实例。理解了“确定性”和“可行性”，才能理解为什么我们在设计算法时要特别关注指针的走向、循环的边界条件和递归的终止条件。
3. **程序实现**：将算法转换为程序时，需要增加数据类型的定义、内存分配和语法实现，但程序的灵魂依然是背后的算法逻辑。

### 0.2 算法分析<a id = "0.2"></a>

在编写出正确的算法之后，我们面临的核心问题往往是：**这个算法有多快？它占不占内存？** 算法分析正是用于定量评估算法性能的理论工具。它不依赖于具体的编程语言或硬件，而是通过数学方法来描述算法的资源消耗（主要是时间和空间）随输入规模增长的变化趋势。

#### 一、时间复杂度（Time Complexity）

时间复杂度衡量的是算法运行所需的时间随输入规模 $n$ 增长而增长的速率。我们通常不关心绝对运行时间（受硬件影响），而是关注**基本操作执行次数**的增长量级。

##### 1.1 三种常见情况
根据输入数据的不同状态，算法的运行时间可能有巨大差异：

- **最坏情况（Worst Case）**：算法在任意输入下运行时间的**上界**。记为 $T(n)$。
  - *意义*：这是算法性能的“底线”，是衡量算法优劣最常用的指标。例如，快速排序的最坏情况是 $O(n^2)$（基准元素始终为极端值时）。
- **最好情况（Best Case）**：算法在最优输入下的运行时间。
  - *意义*：参考意义较小，因为这种情况通常不常见或难以遇到。例如，二分查找的最好情况是 $O(1)$（第一次就找到目标）。
- **平均情况（Average Case）**：算法在所有可能输入下的运行时间的**数学期望**。
  - *意义*：最能反映算法的实际表现，但计算通常非常复杂（需要假设输入的概率分布）。例如，随机化快速排序的平均情况是 $O(n \log n)$。

##### 1.2 常见时间复杂度量级
以下按性能从优到劣排列：

1. **$O(1)$ 常数阶**：运行时间与输入规模无关。如数组索引、哈希表查找。
2. **$O(\log n)$ 对数阶**：非常高效。如二分查找、平衡树查找。
3. **$O(n)$ 线性阶**：时间随输入规模线性增长。如顺序查找。
4. **$O(n \log n)$ 线性对数阶**：分治算法的典型复杂度。如归并排序、堆排序。
5. **$O(n^2)$ 平方阶**：双重循环的复杂度。如冒泡排序、选择排序。
6. **$O(n^3)$ 立方阶**：三重循环。如部分矩阵乘法。
7. **$O(2^n)$ 指数阶**：递归穷举。如无优化的斐波那契数列求解。
8. **$O(n!)$ 阶乘阶**：极为灾难的复杂度。如旅行商问题的暴力解法（$n$ 个城市的全排列）。

#### 二、渐近记号（Asymptotic Notations）

为了精确描述算法在输入趋向无穷大时的极限行为，我们使用以下数学符号。

##### 2.1 大 $O$ 记号（Big-O Notation）
- **定义**：若存在正常数 $c$ 和 $n_0$，使得对所有 $n \ge n_0$，有 $0 \le f(n) \le c \cdot g(n)$，则记为 $f(n) = O(g(n))$。
- **含义**：表示 $g(n)$ 是 $f(n)$ 的**上界**（最坏情况）。用于描述算法在最坏情况下的时间复杂度。
- *例*：$3n^2 + n = O(n^2)$，$2^n + n^3 = O(2^n)$。

##### 2.2 大 $\Omega$ 记号（Big-Omega Notation）
- **定义**：若存在正常数 $c$ 和 $n_0$，使得对所有 $n \ge n_0$，有 $0 \le c \cdot g(n) \le f(n)$，则记为 $f(n) = \Omega(g(n))$。
- **含义**：表示 $g(n)$ 是 $f(n)$ 的**下界**（最好情况）。用于描述算法在最好情况下的时间复杂度。
- *例*：$n^3 + n^2 = \Omega(n^3)$。

##### 2.3 大 $\Theta$ 记号（Big-Theta Notation）
- **定义**：若存在正常数 $c_1, c_2$ 和 $n_0$，使得对所有 $n \ge n_0$，有 $0 \le c_1 g(n) \le f(n) \le c_2 g(n)$，则记为 $f(n) = \Theta(g(n))$。
- **含义**：表示 $g(n)$ 是 $f(n)$ 的**渐进紧确界**（精确量级）。当上界和下界重合时使用。
- *例*：$2n^2 + n = \Theta(n^2)$。

##### 2.4 小 $o$ 与 小 $\omega$（拓展）
- **小 $o$**：$f(n) = o(g(n))$ 表示 $f(n)$ 的增长率**严格小于** $g(n)$（如 $n = o(n^2)$）。
- **小 $\omega$**：$f(n) = \omega(g(n))$ 表示 $f(n)$ 的增长率**严格大于** $g(n)$（如 $n^2 = \omega(n)$）。

#### 三、空间复杂度（Space Complexity）

空间复杂度衡量的是算法运行过程中**临时占用的内存空间**随输入规模 $n$ 增长而增长的速率。

- **构成**：
  - **固定空间**：与输入规模和输出无关的空间（如常量、简单变量、程序代码）。
  - **可变空间**：随输入规模变化的空间（如动态分配的数组、递归调用栈）。
- **常见量级**：
  - $O(1)$：原地排序（如插入排序、堆排序）。
  - $O(n)$：需要额外数组或递归深度与 $n$ 成正比（如归并排序的辅助数组）。
  - $O(\log n)$：递归栈深度（如二分查找）。
- **权衡（Trade-off）**：在某些算法中，**空间换时间**是常见策略（如动态规划中存储子问题解、哈希表的查找）。

#### 四、递归算法复杂度分析

递归算法将问题分解为子问题，其复杂度通常需要通过递推方程求解。

##### 4.1 三种求解方法
1.  **代入法（Substitution Method）**：
    - 先猜测复杂度形式（如 $T(n) = O(n \log n)$），然后利用数学归纳法证明。
    - *适用*：思路直观，但依赖猜测技巧。

2.  **递归树法（Recursion Tree Method）**：
    - 将递推关系画成树状结构，计算每层的代价，然后求和得到总代价。
    - *适用*：直观理解分治过程（如归并排序的递归树）。

3.  **主定理（Master Theorem）**：
    - 针对形如 $T(n) = aT(n/b) + f(n)$ 的递推式（其中 $a \ge 1, b > 1$）。
    - **结论**：
      - 若 $f(n) = O(n^{\log_b a - \epsilon})$，则 $T(n) = \Theta(n^{\log_b a})$。
      - 若 $f(n) = \Theta(n^{\log_b a} \log^k n)$，则 $T(n) = \Theta(n^{\log_b a} \log^{k+1} n)$。
      - 若 $f(n) = \Omega(n^{\log_b a + \epsilon})$，且满足正则条件 $a f(n/b) \le c f(n)$（$c < 1$），则 $T(n) = \Theta(f(n))$。
    - *示例*：归并排序 $T(n)=2T(n/2)+O(n)$ $\Rightarrow$ $T(n)=\Theta(n\log n)$。

#### 五、摊还分析（Amortized Analysis）

摊还分析用于评估一组操作（如数据结构操作序列）的**平均**性能，以证明尽管个别操作可能很昂贵，但总成本在长期运行中仍然很低。

##### 5.1 聚集法（Aggregate Method）
- 直接计算 $n$ 个操作总时间 $T(n)$，然后除以 $n$ 得到摊还成本。
- *例*：动态数组（Vector/ArrayList）每次插入扩容时需 $O(n)$ 复制，但 $n$ 次插入总成本仅 $O(n)$，摊还 $O(1)$。

##### 5.2 记账法（Accounting Method）
- 为每个操作分配“存款”（不同于实际成本）。将“存款”存放在数据结构中的对象（如硬币）上，用于支付未来高昂的操作。
- *例*：动态数组扩容时，用之前多余存款支付复制成本。

##### 5.3 势能法（Potential Method）
- 定义数据结构整体的势能函数 $\Phi(D_i)$。摊还成本 $\hat{c}_i$ 等于实际成本 $c_i$ 加上势能变化：$\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1})$。
- 总摊还成本 = 总实际成本 + 总势能差。若势能函数设计合理（初始势能0，始终非负），则摊还成本是实际成本的上界。

#### 六、小结

算法分析是设计高效程序的基石。你需要重点掌握：
1.  **复杂度度量**：明确最坏情况（$O$）、最好情况（$\Omega$）和平均情况的分析场景。
2.  **渐近记号**：熟练区分 $O$、$\Omega$、$\Theta$ 的含义，避免混淆上界和紧确界。
3.  **空间意识**：在时间效率满足要求时，关注空间开销，理解时空权衡。
4.  **递归分析**：能够用主定理快速求解常见分治算法的复杂度。
5.  **摊销思维**：理解像动态数组、伸展树等数据结构平滑操作成本的思路。

### 0.3 数据结构基本概念<a id = "0.3"></a>

在了解了算法的定义与分析之后，本节正式进入数据结构的核心领域。数据结构不是简单的“数据的容器”，而是研究如何**组织、存储和管理数据**，以使算法能够高效地访问和操作它们。本节将明确数据结构的定义，并建立从“逻辑结构”到“物理结构”再到“抽象数据类型”的完整认知框架。

#### 一、数据结构的基本定义

**数据结构（Data Structure）** 是计算机存储、组织数据的方式。它关注数据元素之间的相互关系，以及定义在这些关系上的操作。

在计算机科学中，有一个著名的公式：
> **程序 = 数据结构 + 算法**

这强调了数据结构与算法是同等重要的两个支柱。一个精心设计的数据结构能够显著提升算法的效率，而一个低效的数据结构则可能成为整个系统的瓶颈。

#### 二、数据的逻辑结构（Logical Structure）

逻辑结构是从**用户或程序员视角**出发，描述数据元素之间**抽象的、独立于物理存储**的相互关系。它主要分为以下四大类：

##### 2.1 集合结构（Set）
- **特征**：数据元素之间除了“同属于一个集合”之外，没有其他任何关系。
- **举例**：数学中的无序集合，或者编程语言中的 `HashSet`。
- **特点**：元素之间是松散的，唯一需要关注的是“是否存在”或“是否属于”。

##### 2.2 线性结构（Linear）
- **特征**：数据元素之间存在**一对一的线性关系**。除了第一个和最后一个元素外，每个元素都有且仅有一个前驱和一个后继。
- **举例**：数组、链表、栈、队列。
- **特点**：数据在逻辑上排列成一条“线”，遍历方向明确。

##### 2.3 树形结构（Tree）
- **特征**：数据元素之间存在**一对多的层次关系**。每个元素（节点）可以有多个后继（子节点），但通常只有一个前驱（父节点），根节点除外。
- **举例**：文件系统目录、二叉搜索树、堆。
- **特点**：具有明显的层级和分支，是“非线性”但有序的结构。

##### 2.4 图形结构（Graph）
- **特征**：数据元素之间存在**多对多的网状关系**。任意两个元素之间都可以存在连接（边），没有严格的层级限制。
- **举例**：社交网络、地图导航、电路网络。
- **特点**：最为复杂的逻辑结构，可以表达任何复杂的关系网。

#### 三、数据的物理结构（物理存储结构）

物理结构描述数据在计算机存储器（如内存、磁盘）中的**具体存储映像**。它关注的是数据“实际上是怎么存放的”，而不仅仅是“逻辑上怎么排列的”。主要分为两种：

##### 3.1 顺序存储结构（Sequential Storage）
- **定义**：将逻辑上相邻的数据元素，存储在物理地址上也相邻的存储单元中。
- **典型代表**：数组（Array）。
- **优点**：支持**随机访问**（通过下标直接定位），访问速度快。
- **缺点**：插入和删除操作效率较低，通常需要移动大量元素；且需要预先分配连续的内存空间，容易造成空间浪费或溢出。

##### 3.2 链式存储结构（Linked Storage）
- **定义**：将数据元素存储在物理上不一定相邻的存储单元中，通过指针（或引用）链接这些单元以表达逻辑关系。
- **典型代表**：单链表、双链表、树的孩子兄弟表示法。
- **优点**：插入和删除操作灵活，无需移动其他元素；不需要连续的内存空间，内存利用率高。
- **缺点**：不支持随机访问（查找需要遍历）；需要额外的存储空间来存放指针。

##### 3.3 索引存储与散列存储（补充）
- **索引存储**：在存储数据的同时，建立一个索引表，通过索引快速定位数据（如数据库索引）。
- **散列存储**：通过哈希函数直接计算出数据元素的存储地址（如哈希表），兼具随机访问和动态增删的优点，但存在哈希冲突问题。

#### 四、抽象数据类型（ADT, Abstract Data Type）

##### 4.1 定义
抽象数据类型（ADT）是指一个数学模型以及定义在该模型上的一组操作。它强调**接口与实现的分离**：用户只关心“能做什么”（操作语义），而不关心“怎么做”（底层实现）。

##### 4.2 三元组表示
ADT 通常用三元组来描述：
> **ADT = (数据对象, 数据关系, 基本操作)**

- **数据对象**：定义操作所作用的实体集合（如整数、字符）。
- **数据关系**：定义这些实体之间的逻辑约束（如线性、树形）。
- **基本操作**：定义可对数据施加的行为（如插入、删除、查找）。

##### 4.3 示例：栈的 ADT
```
ADT Stack {
数据对象：D = { ai | ai ∈ ElemType, i = 1..n, n ≥ 0 }
数据关系：R = { <ai, ai+1> | ai, ai+1 ∈ D, 1 ≤ i < n }
基本操作：
InitStack(&S) // 初始化空栈
Push(&S, e) // 入栈
Pop(&S, &e) // 出栈
GetTop(S, &e) // 取栈顶元素
StackEmpty(S) // 判空
}
```
##### 4.4 ADT 的意义
- **封装性**：隐藏了实现的细节（如底层是用数组还是链表），用户只需调用标准接口。
- **可复用性**：同样的 ADT（如栈）可以在不同场景下使用，且可以根据性能需求选择不同的实现方式。
- **工程化基础**：在现代软件开发中，ADT 是面向对象编程和泛型编程的理论基石。

#### 五、逻辑结构、物理结构与ADT的关系

为了更清晰地理解这三者的层次，可以用一个类比来概括：

| 层次 | 关注点 | 类比（图书馆） | 计算机实例 |
| :--- | :--- | :--- | :--- |
| **逻辑结构** | 数据之间“是什么关系” | 书籍在书架上按分类号排列（如文学类、科技类） | 数组的线性、二叉树的层次 |
| **物理结构** | 数据“实际放在哪里” | 具体的书架格子位置（如 3 楼 A 区 5 架） | 连续内存地址、链表散落地址 |
| **ADT** | 数据“能做什么操作” | 图书馆提供的借书、还书、检索服务接口 | 栈的 push/pop、队列的 enqueue/dequeue |

#### 六、小结

数据结构的基本概念是后续所有章节的基石。你需要重点掌握：
1. **逻辑结构**：能够将实际问题抽象为集合、线性、树形或图形结构。
2. **物理结构**：理解顺序存储与链式存储的本质差异，以及它们对算法性能的影响。
3. **ADT**：建立“接口隔离实现”的思维模式，为后续学习抽象容器（如 STL、Java Collections）打下基础。

## 第一章：线型数据结构<a id = "第一章"></a>
### 1.1 数组（Array）<a id = "1.1"></a>

数组是最基础、最常用的线性数据结构。它在内存中占据一片**连续**的存储空间，通过**下标（索引）** 访问元素，支持高效的随机访问。数组是许多高级数据结构（如栈、队列、哈希表）的底层实现基础。

#### 一、数组的定义与特性

##### 1.1 定义
数组是由**相同类型**的元素组成的有限集合，这些元素按一定顺序排列，每个元素通过一个唯一的**下标**（索引）标识。一维数组可视为线性表，多维数组则是线性表的推广。

**形式化定义**：设数组名为 $A$，包含 $n$ 个元素，则 $A = (a_0, a_1, \dots, a_{n-1})$，其中 $a_i$ 表示第 $i$ 个元素（通常下标从 0 开始）。

##### 1.2 重要特性
1. **连续存储**：所有元素在内存中占据连续地址。
2. **相同类型**：每个元素的大小（字节数）相同，因此可以通过**基地址 + 偏移量**直接定位任意元素。
3. **随机访问**：访问任意位置的时间复杂度为 $O(1)$（只要知道下标）。
4. **固定长度**（静态数组）：一旦创建，长度通常不可变（除非使用动态数组）。

##### 1.3 数组的索引
在大多数编程语言中，数组下标从 0 开始（如 C、C++、Java、Python 的列表）。从 0 开始可简化地址计算，并符合数组在内存中的偏移量设计。

#### 二、数组的存储结构

##### 2.1 一维数组的存储
假设数组 $A$ 的基地址为 $base$，每个元素占用 $size$ 个字节，则元素 $a_i$ 的地址为：
$$ \text{address}(a_i) = base + i \times size $$

##### 2.2 多维数组的存储
多维数组（如二维数组）在内存中有两种常见的存储方式：
- **行主序（Row-major order）**：按行依次存储，C/C++ 使用此方式。对于二维数组 $A[m][n]$，元素 $A[i][j]$ 的地址为：
$$ \text{address}(A[i][j]) = base + (i \times n + j) \times size $$
- **列主序（Column-major order）**：按列依次存储，Fortran、MATLAB 使用此方式。地址公式为：
$$ \text{address}(A[i][j]) = base + (j \times m + i) \times size $$

#### 三、数组的基本操作

| 操作 | 描述 | 时间复杂度 |
|------|------|------------|
| 访问（Access） | 通过下标获取元素值 | $O(1)$ |
| 修改（Update） | 通过下标修改元素值 | $O(1)$ |
| 插入（Insert） | 在指定位置插入新元素，需后移元素 | 平均 $O(n)$，最坏 $O(n)$ |
| 删除（Delete） | 删除指定位置元素，需前移元素 | 平均 $O(n)$，最坏 $O(n)$ |
| 查找（Search） | 按值查找（无序数组） | 平均 $O(n)$（顺序查找） |
| 查找（Search） | 按值查找（有序数组，二分查找） | $O(\log n)$ |

> 注意：插入和删除在**末尾**操作时，若数组有预分配空间，可达到 $O(1)$（需维护当前长度）。

#### 四、多维数组与矩阵

- **二维数组**：可视为“数组的数组”，常用于表示矩阵、图像、表格。
- **三维及以上**：用于张量计算（如深度学习中的多维张量）。
- **特殊矩阵**：
  - **对称矩阵**、**三角矩阵**等可压缩存储为一位数组，节省空间。
  - **稀疏矩阵**：使用三元组（行、列、值）或十字链表存储，避免存储大量零元素。

#### 五、静态数组与动态数组

##### 5.1 静态数组（Static Array）
- 在编译时确定大小，分配在栈上或全局数据区。
- 优点：速度快，无额外内存开销。
- 缺点：大小固定，无法动态扩容。

##### 5.2 动态数组（Dynamic Array / Vector / ArrayList）
- 在堆上分配内存，可以动态调整大小。
- **扩容策略**：当数组满时，分配更大内存（通常为原大小的 1.5 或 2 倍），复制原有元素。
- **摊还分析**：动态数组的插入（末尾）摊还时间复杂度为 $O(1)$（因扩容虽然 $O(n)$，但发生次数少）。
- **实现**：如 C++ 的 `std::vector`、Java 的 `ArrayList`、Python 的 `list`。

##### 5.3 动态数组与静态数组对比

| 特性 | 静态数组 | 动态数组 |
|------|----------|----------|
| 大小 | 固定 | 可变 |
| 存储位置 | 栈/全局 | 堆 |
| 扩容 | 不支持 | 支持 |
| 空间利用率 | 高 | 可能稍低（预分配） |
| 插入/删除（末尾） | $O(1)$（若未满） | 摊还 $O(1)$ |

#### 六、数组的优缺点

##### 优点
- **随机访问**：$O(1)$，适合频繁按索引读取。
- **存储密度高**：无需存储指针，仅存储数据本身。
- **缓存友好**：连续内存，有利于 CPU 缓存命中。

##### 缺点
- **插入/删除**：中间位置操作需移动大量元素，效率低。
- **固定大小**：静态数组无法动态扩容（动态数组虽解决，但扩容有开销）。
- **内存连续性要求**：需要足够大的连续内存块，可能造成空间浪费。

#### 七、典型应用

- **实现其他数据结构**：栈、队列、堆、哈希表等。
- **存储矩阵**：图像处理、线性代数。
- **排序和查找**：数组是众多算法的直接操作对象。
- **字符串**：在 C 语言中，字符串本质是字符数组。

#### 八、典型例题

##### 例1：动态数组的扩容
假设初始容量为 4，每次扩容为 2 倍，插入 9 个元素，求总复制次数。
- 插入第 5 个元素时扩容（复制 4 个），第 9 个元素时再次扩容（复制 8 个），总复制次数 = 4 + 8 = 12。

##### 例2：二维数组地址计算
已知二维数组 $A[10][20]$，行主序，$base=1000$，每个元素 4 字节，求 $A[3][5]$ 的地址。
$$ \text{address} = 1000 + (3 \times 20 + 5) \times 4 = 1000 + 65 \times 4 = 1260 $$

##### 例3：数组旋转（LeetCode 189）
给定数组，向右旋转 k 步。可用三次反转法（$O(n)$ 时间，$O(1)$ 空间）。

#### 九、小结

数组是数据结构的基础。你需要掌握：
1. 数组的定义、连续存储和随机访问特性。
2. 一维和多维数组的地址计算公式。
3. 基本操作的时间复杂度。
4. 静态数组与动态数组的区别与实现（扩容策略）。
5. 数组的优缺点及典型应用场景。

### 1.2 链表（Linked List）<a id = "1.2"></a>

链表是一种**物理上不连续、逻辑上连续**的线性数据结构。它通过“指针”或“引用”将一系列数据节点串联在一起，从而弥补了数组在插入、删除操作上效率低的不足。链表是动态内存管理的典型代表。

#### 一、链表的定义与特点

##### 1.1 定义
链表是由 $n$（$n \ge 0$）个节点组成的有限序列。每个节点包含两个部分：
- **数据域（Data）**：存储该节点的数据元素。
- **指针域（Next）**：存储指向下一个节点的地址（或引用）。

当 $n = 0$ 时，称为空链表。

##### 1.2 核心特点
1. **非连续存储**：节点在内存中的位置是分散的，依靠指针链接。
2. **动态大小**：无需预先分配内存，可根据需要随时申请或释放节点。
3. **顺序访问**：不支持随机访问，只能从表头开始逐个遍历（时间复杂度 $O(n)$）。

#### 二、链表的分类

根据指针域的设置和链表的连接方式，链表主要分为以下三类：

##### 2.1 单向链表（Singly Linked List）
- **结构**：每个节点包含数据域和**一个**指向后继节点的指针（`next`）。
- **特点**：只能从前往后单向遍历。最后一个节点的 `next` 指向 `NULL`（或 `nullptr`）。
- **表示**：`Head` 指针指向第一个节点（头节点）。

##### 2.2 双向链表（Doubly Linked List）
- **结构**：每个节点包含数据域、指向**后继**节点的指针（`next`）和指向前驱节点的指针（`prev`）。
- **特点**：支持双向遍历。查找某个节点的前驱时，无需从头开始遍历。
- **优势**：插入和删除操作更灵活（已知节点位置时，可 $O(1)$ 完成），但需要额外的空间存储 `prev` 指针。

##### 2.3 循环链表（Circular Linked List）
- **结构**：链表中最后一个节点的指针不指向 `NULL`，而是指向**头节点**（或第一个节点），形成一个环。
- **分类**：
  - **单向循环链表**：仅有 `next` 指针，且尾部指向头部。
  - **双向循环链表**：既有 `next` 也有 `prev`，头部 `prev` 指向尾部，尾部 `next` 指向头部。
- **特点**：从任意节点出发，都能遍历到整个链表，适合解决约瑟夫环问题。

##### 2.4 静态链表（Static Linked List）——扩展
- **定义**：使用数组来模拟链式结构。数组中的每个元素（游标）既存储数据，也存储“下一个元素”在数组中的下标（称为游标 `cur`）。
- **特点**：兼备数组的“静态”和链表的“链式”特点，通常在没有指针的低级语言（如早期的 BASIC）或操作系统内核中使用。

#### 三、节点结构（C语言版）

```c
// 单向链表节点
typedef struct Node {
    int data;               // 数据域
    struct Node* next;      // 指针域
} Node;

// 双向链表节点
typedef struct DNode {
    int data;
    struct DNode* prev;
    struct DNode* next;
} DNode;
```
#### 四、基本操作与时间复杂度

链表的核心操作包括查找、插入和删除。其时间开销主要分为两个部分：**定位目标位置**（查找）和**修改指针**（增删）。与数组不同，链表的插入和删除本身非常快，但查找位置通常需要遍历。

| 操作 | 单向链表 | 双向链表 | 说明 |
| :--- | :--- | :--- | :--- |
| **按值查找** | $O(n)$ | $O(n)$ | 无论是否有序，都必须从头开始逐个遍历。 |
| **按位查找/访问** | $O(n)$ | $O(n)$ | 不支持随机访问，需要移动指针（如访问第 $i$ 个节点）。 |
| **头插法（插入）** | $O(1)$ | $O(1)$ | 直接修改新节点的 `next` 指向原头节点，然后更新头指针。 |
| **尾插法（插入）** | $O(n)$（无尾指针）<br>$O(1)$（有尾指针） | $O(1)$（若有尾指针） | 如果维护了 `tail` 指针，双向链表可以直接通过 `tail->next` 插入。 |
| **已知节点后的插入** | $O(1)$ | $O(1)$ | 只需修改 `p->next` 和新节点的指针，是链表的“拿手好戏”。 |
| **已知节点的删除** | $O(1)$（若已知前驱）<br>$O(n)$（若未知前驱） | $O(1)$（已知节点本身） | 双向链表因包含 `prev` 指针，可在 $O(1)$ 内找到前驱，无需遍历。 |

**核心结论**：
1.  **增删快**：链表的插入和删除操作本身是 $O(1)$ 的（只需移动指针），远优于数组的 $O(n)$。
2.  **查找慢**：按值或按位置查找的效率是 $O(n)$，远低于数组的 $O(1)$ 随机访问。
3.  **适用场景**：链表最适合**数据量动态变化、频繁在中间位置插入或删除**的场景。

#### 五、链表与数组的对比

在选择数据结构时，理解数组与链表的本质区别至关重要。以下是多维度的对比：

| 维度 | **数组（Array）** | **链表（Linked List）** |
| :--- | :--- | :--- |
| **存储方式** | 连续的内存空间（物理相邻）。 | 分散的内存空间（物理不相邻，通过指针关联）。 |
| **空间分配** | 静态分配（固定大小）或动态扩容（需要复制移动）。 | 动态分配（按需申请，即用即建）。 |
| **随机访问** | $O(1)$（根据首地址 + 偏移量直接计算）。 | $O(n)$（需从头开始遍历至目标节点）。 |
| **插入/删除（中间）** | $O(n)$（需移动大量后续元素以腾出/填补空间）。 | $O(1)$（仅修改目标位置的指针指向）。 |
| **插入/删除（末尾）** | $O(1)$（动态数组扩容时偶尔 $O(n)$，摊还分析为 $O(1)$）。 | $O(1)$（若维护了尾指针）。 |
| **缓存友好性** | **极高**。空间局部性好，CPU 预读机制可大幅提升访问速度。 | **极低**。节点散落在堆内存各处，易产生 Cache Miss（缓存未命中）。 |
| **额外空间开销** | 几乎为 0（无需存储指针）。 | 较大（每个节点需额外存储 1~2 个指针，$O(n)$ 空间开销）。 |
| **内存碎片** | 静态数组无碎片；动态数组可能造成内存浪费（预分配）。 | 无外部碎片，但频繁申请释放可能产生内部碎片（取决于内存分配器）。 |

#### 六、典型应用场景

基于链表的特性，它在计算机科学中有以下经典应用：

1.  **操作系统内核**：用于进程管理中的任务队列（就绪队列、阻塞队列）、内存管理中的空闲块链表。
2.  **编译原理与数据结构**：实现哈希表的**链地址法**（拉链法）以解决哈希冲突。
3.  **缓存系统**：**LRU（最近最少使用）缓存淘汰策略**，通常使用 **哈希表 + 双向链表** 的结构，以实现 $O(1)$ 的查找和删除。
4.  **数学计算**：存储稀疏多项式（非零项），便于进行多项式加减法。
5.  **特定算法问题**：解决约瑟夫环问题（循环链表）、文件目录的层级遍历等。
#### 七、典型例题
##### 例1：反转单向链表（LeetCode 206）
思路：迭代法，使用三个指针 prev、curr、next 逐个反转节点的指向。
```c
Node* reverseList(Node* head) {
    Node* prev = NULL;
    Node* curr = head;
    while (curr != NULL) {
        Node* nextTemp = curr->next; // 保存后继
        curr->next = prev;           // 反转指针
        prev = curr;                 // 前移
        curr = nextTemp;
    }
    return prev; // 新头节点
}
```
##### 例2：环形链表检测（LeetCode 141）
思路：快慢指针（Floyd 判圈法）。慢指针每次走一步，快指针每次走两步，若相遇则有环。
```
bool hasCycle(Node* head) {
    if (!head) return false;
    Node* slow = head;
    Node* fast = head->next;
    while (slow != fast) {
        if (!fast || !fast->next) return false;
        slow = slow->next;
        fast = fast->next->next;
    }
    return true;
}
```
##### 例3：双向链表的删除节点（已知节点地址）
给定双向链表中的节点 p，若要求删除 p，只需 $O(1)$：
```
p->prev->next = p->next;
if (p->next) p->next->prev = p->prev;
free(p);
```
#### 八、小结

链表是克服数组“插入删除低效”缺点的核心数据结构。你需要重点掌握：
1.  **结构差异**：单向链表、双向链表、循环链表的内存布局与指针操作。
2.  **效率权衡**：明确链表“增删快、查找慢”的本质，理解其与数组在空间与时间上的取舍。
3.  **指针思维**：在纸上绘制节点和箭头，模拟插入和删除过程中的指针变化，这是学习链表的关键。
4.  **应用认知**：了解链表在操作系统、缓存算法（LRU）中的实际地位。

### 1.3 栈（Stack）<a id = "1.3"></a>

栈（Stack）是一种**操作受限**的线性表。它只允许在线性表的**同一端**（称为栈顶，Top）进行插入和删除操作，这一端通常是表的末端。栈遵循**后进先出**（Last In First Out, LIFO）的原则，即最后放入栈的元素将最先被取出。

#### 一、栈的基本概念与特点

##### 1.1 定义
栈是限定仅在表尾进行插入和删除操作的线性表。允许插入和删除的一端称为**栈顶（Top）**，另一端称为**栈底（Bottom）**。不含任何元素的栈称为**空栈**。

##### 1.2 LIFO 原则
栈的核心特性是后进先出。这类似于现实生活中的“一叠盘子”或“手枪弹匣”：最后放上去的盘子最先被取走，最后压入弹匣的子弹最先被射出。

#### 二、栈的基本操作

一个标准的栈抽象数据类型（ADT）通常支持以下核心操作：

| 操作 | 描述 | 参数 |
| :--- | :--- | :--- |
| **InitStack(&S)** | 初始化一个空栈。 | 栈引用 |
| **Push(&S, e)** | **入栈**：将元素 e 插入到栈顶。 | 栈引用、元素 |
| **Pop(&S, &e)** | **出栈**：删除栈顶元素，并用 e 返回其值。 | 栈引用、元素引用 |
| **GetTop(S, &e)** | **取栈顶**：读取栈顶元素的值，但不出栈。 | 栈、元素引用 |
| **StackEmpty(S)** | **判空**：判断栈是否为空。 | 栈 |

> **注意**：在顺序栈中，通常还需要判断栈是否已满（`StackFull`），以防止溢出。

#### 三、栈的存储结构与实现

栈作为一种逻辑结构，其底层物理实现通常有两种方式：顺序存储和链式存储。

##### 3.1 顺序栈（Sequential Stack）
- **实现方式**：利用**数组**作为底层容器。通常使用一个整型变量 `top` 来指示栈顶元素在数组中的位置。
- **存储结构**：
  - 初始时，`top = -1` 表示空栈。
  - 入栈操作：`top++`，然后将元素存入 `data[top]`。
  - 出栈操作：取出 `data[top]`，然后 `top--`。
- **特点**：
  - **优点**：实现简单，随机访问快（虽然栈不需要随机访问）。
  - **缺点**：数组大小固定，存在栈满（上溢）风险；若分配过大则浪费空间。

###### 双端栈（共享栈）——栈的变体
- **概念**：为了更高效地利用数组空间，可以将**两个栈**的栈底分别设在数组的两端（0 和 `maxsize-1`），两个栈向中间生长。
- **判满条件**：当 `top1 + 1 == top2` 时，两个栈共享的空间已满。
- **优势**：适用于两个栈类型相反（如一个存递增数据，一个存递减数据）或需要协同工作的场景，能有效避免一方空间不足而另一方空间浪费的情况。

##### 3.2 链式栈（Linked Stack）
- **实现方式**：利用**单链表**作为底层容器。通常将单链表的**头结点**作为栈顶。
- **存储结构**：
  - 入栈：相当于在链表头部插入一个新节点（`O(1)`）。
  - 出栈：相当于删除链表头部的第一个节点（`O(1)`）。
- **特点**：
  - **优点**：不存在栈满（上溢）问题（除非内存耗尽），大小动态可变。
  - **缺点**：需要额外的指针域（`next`），存储密度较低。

#### 四、时间复杂度分析

在标准的栈实现中，无论是顺序栈还是链式栈，只要操作发生在栈顶，其时间复杂度都是**常数级**：

- **入栈（Push）**：$O(1)$
- **出栈（Pop）**：$O(1)$
- **取栈顶（Peek/Top）**：$O(1)$
- **判空（IsEmpty）**：$O(1)$

#### 五、栈的典型应用

栈是计算机科学中应用最广泛的数据结构之一，以下是几个经典的场景：

##### 5.1 函数调用与递归（系统栈）
- **原理**：操作系统在运行程序时，会为每个线程分配一个“调用栈”（Call Stack）。
- **作用**：当函数 A 调用函数 B 时，系统会将 A 的返回地址、局部变量等上下文信息**压入**栈中。B 执行完毕后，系统会**弹出** A 的信息，恢复 A 的执行环境。
- **递归**：递归函数的本质就是自己调用自己，系统栈负责管理每次递归调用的参数和返回地址。若递归过深，会导致**栈溢出**（Stack Overflow）。

##### 5.2 表达式求值（后缀表达式）
- **中缀表达式**：如 `(1 + 2) * 3`，人类易读，但计算机处理括号较复杂。
- **后缀表达式**（逆波兰表达式）：如 `1 2 + 3 *`，运算符在操作数之后，无需括号。
- **算法**：利用栈扫描后缀表达式，遇到操作数压栈，遇到运算符则弹出两个操作数计算，再将结果压栈。

##### 5.3 括号匹配（符号平衡）
- **应用**：编译器检查代码中的括号 `( )`、`[ ]`、`{ }` 是否匹配。
- **算法**：扫描字符串，遇到左括号（`(`、`[`、`{`）压入栈；遇到右括号时，弹出栈顶元素，检查是否匹配。若扫描完栈不为空，则说明有未匹配的左括号。

##### 5.4 撤销操作（Undo）与浏览器的后退功能
- **撤销**：在文本编辑器中，每执行一次操作（如输入文字），都将当前状态压入栈。执行撤销时，弹出栈顶状态恢复到前一步。
- **浏览器后退**：记录访问过的网页 URL。点击后退时，弹出当前页面，回到上一页（通常需要维护两个栈：一个用于后退，一个用于前进）。

##### 5.5 深度优先搜索（DFS）
在图或树的遍历中，深度优先搜索（Depth-First Search, DFS）通常需要借助栈（或递归隐式栈）来保存路径上的节点。

#### 六、顺序栈与链式栈的选择

在实际开发中，选择哪种栈取决于具体需求：

| 场景 | 推荐结构 | 理由 |
| :--- | :--- | :--- |
| 数据量固定或最大规模已知 | **顺序栈** | 速度快，无需额外指针，节省内存。 |
| 数据量动态变化、不可预估 | **链式栈** | 不会溢出，灵活扩容。 |
| 两个栈需要共享同一段内存 | **共享栈（双端栈）** | 提高空间利用率。 |

#### 七、典型例题（概念回顾）

##### 例1：入栈出栈序列
假设一个栈的入栈序列为 `1, 2, 3, 4`，则以下哪个出栈序列是不可能的？
- A. `1, 2, 3, 4`（可行：1入1出，2入2出...）
- B. `4, 3, 2, 1`（可行：1,2,3,4全部入栈，然后依次出栈）
- C. `3, 4, 1, 2`（**不可能**：若3先出，则1和2已在栈底，顺序必须是2在1之前出）

##### 例2：括号匹配
输入 `[({})]`，过程：`[` 入栈，`(` 入栈，`{` 入栈，遇到 `}` 匹配 `{`，遇到 `)` 匹配 `(`，遇到 `]` 匹配 `[`，栈空，匹配成功。

#### 八、小结

栈是一种简单但极其强大的数据结构。你需要掌握：
1.  **LIFO 原则**：深刻理解后进先出的逻辑。
2.  **两种实现**：区分顺序栈（数组+top指针）和链式栈（链表头作为栈顶）的实现细节与优劣。
3.  **手写操作**：能够手写 `Push` 和 `Pop` 的伪代码，注意边界条件（栈空、栈满）。
4.  **应用场景**：能够将实际问题（如括号匹配、撤销、递归）抽象为栈的模型来解决。

### 1.4 队列（Queue）<a id = "1.4"></a>

队列是另一种**操作受限**的线性表。与栈的“后进先出”不同，队列遵循**先进先出**（First In First Out, FIFO）的原则。它只允许在表的一端（称为**队尾**，Rear）进行插入操作，而在另一端（称为**队头**，Front）进行删除操作。队列模拟了现实生活中的“排队”场景——先到的人先接受服务。

#### 一、队列的基本概念与特点

##### 1.1 定义
队列是只允许在一端（队尾）插入，在另一端（队头）删除的线性表。不含任何元素的队列称为**空队列**。

##### 1.2 FIFO 原则
队列的核心特性是先进先出。这类似于现实生活中的“银行叫号”或“打印机任务队列”：先排队的人先办理业务，先提交的打印任务先被打印。

#### 二、队列的基本操作

一个标准的队列抽象数据类型（ADT）通常支持以下核心操作：

| 操作 | 描述 | 参数 |
| :--- | :--- | :--- |
| **InitQueue(&Q)** | 初始化一个空队列。 | 队列引用 |
| **EnQueue(&Q, e)** | **入队**：将元素 e 插入到队尾。 | 队列引用、元素 |
| **DeQueue(&Q, &e)** | **出队**：删除队头元素，并用 e 返回其值。 | 队列引用、元素引用 |
| **GetHead(Q, &e)** | **取队头**：读取队头元素的值，但不出队。 | 队列、元素引用 |
| **QueueEmpty(Q)** | **判空**：判断队列是否为空。 | 队列 |

#### 三、队列的存储结构与实现

与栈类似，队列的底层物理实现也有两种主要方式：顺序存储和链式存储。

##### 3.1 顺序队列（循环队列，Circular Queue）
普通数组实现队列存在严重的**“假溢出”**问题：当队尾指针指向数组末尾时，即使数组前部有空闲空间，也无法再插入新元素。**循环队列**是解决此问题的经典方案，它在逻辑上将数组首尾相接，形成一个环。

- **存储结构**：利用数组 `data` 和两个整型指针 `front`（指向队头元素）和 `rear`（指向队尾元素的**下一个位置**）。
- **初始状态**：`front = rear = 0`（表示空队列）。
- **判空条件**：`front == rear`。
- **判满条件**（常用“牺牲一个存储单元”法）：`(rear + 1) % maxSize == front`。这意味着队列最多容纳 `maxSize - 1` 个元素。
- **入队操作**：
  1.  判断是否满：`if ((rear + 1) % maxSize == front)`，若满则溢出。
  2.  赋值：`data[rear] = e`。
  3.  移动队尾指针：`rear = (rear + 1) % maxSize`。
- **出队操作**：
  1.  判断是否空：`if (front == rear)`，若空则下溢。
  2.  取值：`e = data[front]`。
  3.  移动队头指针：`front = (front + 1) % maxSize`。
- **队列长度**（元素个数）：`(rear - front + maxSize) % maxSize`。
- **变种**：如果不使用“牺牲单元”法，也可以额外增加一个 `size` 变量记录当前元素个数，或增加一个 `tag` 变量标记最近一次操作是插入还是删除，这两种方法都能使队列容纳满 `maxSize` 个元素。

##### 3.2 链式队列（Linked Queue）
链式队列使用单链表作为底层容器，通常需要维护两个指针：`front` 和 `rear`，分别指向链表的头节点（队头）和尾节点（队尾）。

- **存储结构**：
  - `front` 指针通常指向链表的**头结点**（不存储数据，方便操作），而 `rear` 指针指向链表的**尾节点**。
- **入队操作**：在链表尾部插入新节点，`rear->next = newNode`，然后更新 `rear` 指向新节点。时间复杂度 $O(1)$。
- **出队操作**：删除头结点后的第一个节点。若删除后队列为空，需将 `rear` 重置为指向头结点。时间复杂度 $O(1)$。
- **优点**：不存在数组溢出的问题（除非内存耗尽），大小动态可变。

#### 四、双端队列（Deque）

双端队列（Deque，Double-Ended Queue）是队列的扩展，它允许在**两端**进行插入和删除操作。

- **输入受限的双端队列**：只允许在一端插入，但两端都可以删除。
- **输出受限的双端队列**：只允许在一端删除，但两端都可以插入。
- **实现**：双端队列既可以用双向链表实现，也可以用数组实现（需要同时支持两端操作）。
- **应用**：常用于滑动窗口问题（如求窗口内的最大值），或在某些需要灵活访问两端的场景中（如浏览器的历史记录）。

#### 五、时间复杂度分析

在标准的队列实现中，所有基本操作（入队、出队、取队头、判空）的时间复杂度均为常数级：

- **顺序队列（循环）**：$O(1)$
- **链式队列**：$O(1)$

#### 六、队列的典型应用

队列是计算机科学中极其重要的结构，尤其体现在“缓冲”和“广度优先”相关的场景中：

##### 6.1 广度优先搜索（BFS）
在图的遍历中，BFS 必须借助队列来实现。算法从起始节点开始，将其入队；然后循环取出队头节点，并将其所有未访问的邻接节点入队。队列保证了节点是按照“距离起点由近及远”的顺序被访问的。

##### 6.2 CPU 调度与资源管理
- **进程调度**：在操作系统中，就绪队列（Ready Queue）用于管理等待 CPU 时间的进程，通常采用抢占式或非抢占式的 FIFO 调度策略。
- **打印任务队列**：多用户共享一台打印机时，打印任务按提交顺序排队等待执行。

##### 6.3 消息队列（Message Queue）
在分布式系统或多线程编程中，消息队列用于解耦生产者和消费者。生产者将消息放入队列，消费者从队列中取出消息处理，实现了异步通信。

##### 6.4 缓冲区（I/O Buffer）
键盘输入、网络数据包接收等场景中，操作系统通常使用队列作为缓冲区，以防止数据丢失（当处理速度跟不上接收速度时）。

#### 七、典型例题（概念回顾）

##### 例1：循环队列长度计算
设循环队列的数组容量为 `maxSize = 10`，当前 `front = 3`，`rear = 7`，求队列中的元素个数。
解：元素个数 = `(rear - front + maxSize) % maxSize = (7 - 3 + 10) % 10 = 4`。

##### 例2：循环队列判满
一个循环队列采用“牺牲一个存储单元”的方式判满，若 `maxSize = 8`，当前 `front = 2`，请问 `rear` 为何值时队列已满？
解：根据判满公式 `(rear + 1) % maxSize == front`，即 `(rear + 1) % 8 == 2`，解得 `rear = 1`。

##### 例3：双端队列的输出受限
若一个输出受限的双端队列（只允许在一端删除），输入序列为 `1, 2, 3, 4`，则不可能得到的输出序列是？
*（思路：由于删除端固定，元素出队的相对顺序受到插入端选择的限制，需分析两端插入的组合可能性）*

#### 八、顺序队列（循环）与链式队列的选择

| 场景 | 推荐结构 | 理由 |
| :--- | :--- | :--- |
| 队列最大长度已知且固定 | **顺序队列（循环）** | 速度快，操作简单，无指针内存开销。 |
| 队列长度动态变化、不可预估 | **链式队列** | 不会因容量不足而溢出，灵活扩容。 |
| 系统内核或高频实时场景 | **顺序队列（循环）** | 时间确定性更强（无动态内存分配的延迟）。 |

#### 九、小结

队列是处理“公平排队”和“层次遍历”的核心数据结构。你需要掌握：

1.  **FIFO 原则**：深刻理解先进先出的逻辑，与栈（LIFO）进行明确区分。
2.  **循环队列**：重点掌握如何通过取模运算实现数组的“环形复用”，并熟练理解“牺牲一个存储单元”的判空/判满条件。
3.  **链式队列**：理解头尾指针 `front` 和 `rear` 在链式结构中的角色，以及如何处理最后一个元素的出队操作。
4.  **双端队列**：了解其在特定算法（如滑动窗口）中的灵活作用。
5.  **应用场景**：能够将实际问题（如 BFS、任务调度）抽象为队列模型来解决。

### 1.5 哈希表（Hash Table）<a id = "1.5"></a>

哈希表（又称散列表）是一种根据关键码值（Key-Value）直接进行访问的数据结构。它通过一个**哈希函数**将任意类型的键（Key）映射到一个数组的索引位置，从而实现 $O(1)$ 的查找、插入和删除操作。哈希表是现代计算机科学中应用最广泛的数据结构之一。

#### 一、核心思想与基本概念

##### 1.1 定义
哈希表由一个**数组**（通常称为槽位，Slot）和**哈希函数**组成。当插入一个键值对 `(key, value)` 时，系统会调用哈希函数计算 `key` 的哈希值，然后将 `value` 存储在数组的对应位置。

##### 1.2 核心组件
1. **表空间（Table）**：一段连续的存储空间（数组）。
2. **哈希函数（Hash Function）**：将输入 `key` 映射为数组下标的函数。
3. **冲突（Collision）**：当两个不同的 `key` 映射到了同一个数组下标时，就发生了冲突。
4. **负载因子（Load Factor）**：$\alpha = \frac{n}{m}$，其中 $n$ 是表中已存储的元素个数，$m$ 是表长。负载因子决定了哈希表的“拥挤”程度。

#### 二、哈希函数

一个好的哈希函数应当具备以下特性：**确定性**（同一个 key 永远映射到同一个索引）、**均匀性**（key 能均匀分布，减少冲突）以及**高效性**（计算速度快）。常见的哈希函数有：

##### 2.1 除留余数法（Division Method）
$$ hash(key) = key \mod p $$
其中 $p$ 是一个不大于表长 $m$ 的质数（或素数）。选择质数可以显著降低哈希冲突的概率（因为质数在取模时能保证余数的分布更均匀）。这是最常用、最简单的方法。

##### 2.2 乘法哈希（Multiplication Method）
$$ hash(key) = \lfloor m \cdot (key \cdot A \mod 1) \rfloor $$
其中 $A$ 是一个介于 0 和 1 之间的常数（通常取 $\frac{\sqrt{5} - 1}{2} \approx 0.618$）。这种方法对底数分布不敏感，即使 key 有规律，也能产生较好的随机分布，在浮点数计算中常见。

##### 2.3 全域哈希（Universal Hashing）
全域哈希是指在程序开始时，随机从一个精心设计的哈希函数族中选取一个函数。由于攻击者无法提前知道具体选用了哪个函数，可以有效防止恶意输入故意制造大量冲突，从而保证哈希表在面对恶意数据时的安全性，避免退化为 $O(n)$。

#### 三、冲突解决方法

当哈希函数产生冲突时，必须有一种策略来处理。主要有两大类方法：**链地址法**（拉链法）和**开放地址法**。

##### 3.1 链地址法（Separate Chaining）
- **原理**：数组的每个槽位不再直接存储元素，而是存储一个链表（或红黑树、动态数组）的头指针。发生冲突的元素被插入到同一槽位的链表中。
- **操作**：
  - 插入：计算索引，将新节点插入对应链表的头部（$O(1)$）或尾部。
  - 查找：计算索引，遍历链表查找匹配的 key。
  - 删除：计算索引，在链表中删除节点。
- **优点**：
  - 实现简单，删除操作方便（只需在链表中删除节点）。
  - 抗冲突能力强；即使负载因子较高，性能下降也相对平缓（仅影响链表长度）。
  - 表空间利用率高（允许负载因子大于 1）。
- **缺点**：
  - 需要额外的指针内存开销。
  - 缓存不友好（链表节点在内存中分散）。

###### 优化策略（红黑树退化）
在 Java 8 的 `HashMap` 中，当链表的长度超过阈值（如 8）时，链表会转换为红黑树，将最坏情况下的查找时间复杂度从 $O(n)$ 优化为 $O(\log n)$。

##### 3.2 开放地址法（Open Addressing）
- **原理**：所有元素都存储在数组本身中，不额外使用链表。当发生冲突时，按照预定的规则在数组中探测下一个空闲位置。
- **优点**：不需要额外的指针空间，内存利用率高，缓存友好。
- **缺点**：表空间有限，负载因子必须小于 1（通常 $\le 0.75$）；删除操作较复杂（通常需要“懒惰删除”，即标记为删除而非真的删除）。

###### 3.2.1 线性探测（Linear Probing）
- **规则**：当 $hash(key)$ 被占用时，依次检查 $hash(key) + 1, +2, \dots$，直到找到空位。
- **公式**：$H_i = (hash(key) + i) \mod m$（$i = 0, 1, 2, \dots$）。
- **优点**：实现极其简单，对 CPU 缓存极其友好。
- **缺点**：容易产生**主聚集（Primary Clustering）**，即连续被占用的槽位越来越长，导致后续插入的探测时间大幅增加。

###### 3.2.2 二次探测（Quadratic Probing）
- **规则**：探测步长按平方增长。
- **公式**：$H_i = (hash(key) + c_1 i + c_2 i^2) \mod m$，通常简化为 $H_i = (hash(key) + i^2) \mod m$。
- **优点**：有效缓解了线性探测的“主聚集”问题。
- **缺点**：可能产生**二次聚集**，即多个 key 遵循相同的探测路径；且无法保证一定能探测到所有空槽位（需要表长 $m$ 是素数且负载因子小于 0.5 才能保证找到空位）。

###### 3.2.3 双重哈希（Double Hashing）
- **规则**：使用两个独立的哈希函数 $H_1$ 和 $H_2$ 来确定探测序列。
- **公式**：$H_i = (H_1(key) + i \cdot H_2(key)) \mod m$。
- **优点**：探测序列完全由 key 决定，几乎消除了聚集现象，分布接近理想状态。
- **缺点**：计算量相对较大，且需要精心设计 $H_2$（通常要求 $H_2(key)$ 与 $m$ 互质）。

##### 3.3 再哈希法（Rehashing）
这是链地址法或开放地址法的一种变体思路：准备多个哈希函数，如果第一个函数发生冲突，则尝试第二个、第三个……直至找到空位。双重哈希可以看作再哈希法的经典实现。

#### 四、动态扩容与负载因子

##### 4.1 为何需要扩容
随着元素的增加，负载因子 $\alpha$ 不断增大，冲突概率急剧上升，导致操作效率从 $O(1)$ 向 $O(n)$ 退化。为了维持高效的性能，必须在负载因子超过阈值（通常为 0.75）时进行扩容。

##### 4.2 扩容与再哈希（Rehashing）过程
1. **申请新空间**：创建一张新的数组，容量通常是原数组的 **2 倍**（或 `1.5` 倍）。
2. **重新插入**：遍历旧数组中的每个元素，**重新计算哈希值**（因为表长变了，`mod` 的结果也变了），并将其插入到新的数组中。
3. **释放旧表**：将旧表内存回收。

##### 4.3 摊还分析（Amortized Analysis）
虽然一次扩容需要 $O(n)$ 的时间，但扩容发生的间隔越来越长（随着容量指数增长）。因此，**动态哈希表的插入操作摊还（平均）时间复杂度为 $O(1)$**，这与动态数组（Vector）的扩容原理一致。

#### 五、高级变体

##### 5.1 完美哈希（Perfect Hashing）
- **定义**：适用于**静态集合**（即 keys 固定，不再插入删除）。通过两级的哈希结构（一级哈希表和二级哈希表），保证查找操作在最坏情况下也只需要 $O(1)$ 时间，且没有冲突。
- **应用**：编译器中的关键字保留字查找、静态字典。

##### 5.2 布谷鸟哈希（Cuckoo Hashing）
- **原理**：使用两个（或多个）独立的哈希函数和两张表（或一张表的两个区域）。插入时，如果某个 key 的位置被占用，它会“踢出”占位者，让占位者重新寻找自己的另一个哈希位置。如此循环，直到所有 key 都安定下来。
- **特点**：查找操作保证最坏情况 $O(1)$（只需检查固定的几个位置）。插入操作可能需要较长时间，甚至需要扩容来打破循环。

#### 六、复杂度分析

| 操作 | 平均时间复杂度 | 最坏时间复杂度 | 备注 |
| :--- | :--- | :--- | :--- |
| **查找（Search）** | $O(1)$ | $O(n)$ | 当所有 key 发生冲突时退化为链表扫描 |
| **插入（Insert）** | $O(1)$ | $O(n)$ | 扩容（Rehash）时瞬间为 $O(n)$，但摊还为 $O(1)$ |
| **删除（Delete）** | $O(1)$ | $O(n)$ | 链地址法操作链表头节点为 $O(1)$ |

#### 七、典型应用场景

哈希表凭借其 $O(1)$ 的查找速度，在计算机科学中无处不在：

1. **字典与集合（Dict / Set）**：Python 的 `dict`、Java 的 `HashMap`、C++ 的 `unordered_map`。
2. **缓存系统（Cache）**：如 **LRU Cache**（最近最少使用缓存），通常使用 **哈希表 + 双向链表** 的结构实现，实现 $O(1)$ 的查找和移动。
3. **数据库索引**：部分 NoSQL 数据库（如 Redis）使用哈希表作为底层数据结构存储键值对。
4. **编译器与解释器**：维护符号表，快速查找变量名或函数名对应的内存地址/对象。
5. **网络安全**：IP 路由查找、字符串匹配中的快速子串查找（如 Rabin-Karp 算法利用哈希）。

#### 八、小结

哈希表是“空间换时间”思想的巅峰之作。你需要掌握：

1.  **核心三要素**：数组 + 哈希函数 + 冲突解决策略。
2.  **冲突策略的权衡**：
    - **链地址法**：简单、稳定，适合写多读少、表空间不受限的场景。
    - **开放地址法**：节省内存、缓存友好，适合读多写少、表空间紧张的场景。
3.  **动态扩容机制**：理解负载因子的意义以及 Rehash 的摊还分析，这是工程实现的关键。
4.  **局限性**：哈希表是无序的，不支持高效的范围查询（如找出所有在 $[10, 20]$ 之间的 key），且性能严重依赖哈希函数的质量。

## 第二章：树形数据结构<a id = "第二章"></a>
### 2.1 树的基本概念<a id = "2.1"></a>

树是一种非线性数据结构，用于表示具有层次关系的数据。树由节点（Node）和边（Edge）组成，每个节点可以有多个子节点，但只有一个父节点（根节点除外）。本节介绍树的基本术语、性质以及常见表示方法。

#### 一、树的定义与术语

##### 1.1 树的定义
树（Tree）是 $n$（$n \ge 0$）个节点的有限集合。当 $n = 0$ 时称为空树。对于非空树：
- 有且仅有一个称为**根（Root）**的节点。
- 其余节点可分为 $m$（$m \ge 0$）个互不相交的有限集合 $T_1, T_2, \dots, T_m$，每个集合本身又是一棵树，称为根节点的**子树（Subtree）**。

##### 1.2 基本术语
- **节点（Node）**：树中的基本元素，包含数据及指向子节点的引用。
- **边（Edge）**：连接父节点与子节点的连线。
- **根节点（Root）**：树中没有父节点的节点（唯一）。
- **叶子节点（Leaf）**：没有子节点的节点（度数为0）。
- **内部节点（Internal Node）**：非叶子节点。
- **父节点（Parent）**：若节点 $A$ 有子节点 $B$，则 $A$ 是 $B$ 的父节点。
- **子节点（Child）**：$B$ 是 $A$ 的子节点。
- **兄弟节点（Sibling）**：具有相同父节点的节点。
- **祖先（Ancestor）**：从根节点到某节点路径上的所有节点（包括自身？通常不包括自身，但有时定义包含，需注意）。
- **后代（Descendant）**：某节点的子树中所有节点。
- **深度（Depth）**：从根节点到该节点的路径长度（根深度为0）。
- **高度（Height）**：从该节点到其最远叶子节点的路径长度。树的高度为根的高度。
- **层数（Level）**：根为第1层（或0层，不同教材定义不同）。

##### 1.3 度的概念
- **节点的度（Degree）**：节点拥有的子节点个数。
- **树的度**：树中所有节点的最大度数。

#### 二、树的分类（按子节点数量）

##### 2.1 有序树与无序树
- **有序树（Ordered Tree）**：子节点之间有顺序关系（如二叉树中左子与右子不同）。
- **无序树（Unordered Tree）**：子节点之间无顺序区别。

##### 2.2 二叉树（Binary Tree）
每个节点最多有两个子节点（左子节点、右子节点），是计算机科学中最常用的树结构。详见后续章节。

##### 2.3 多叉树（Multiway Tree）
每个节点可以有多个子节点（如三叉树、四叉树等）。常见的有B树、B+树等。

#### 三、树的性质

1. 树中的节点数等于边数加1：$n = e + 1$（其中 $n$ 为节点数，$e$ 为边数）。
2. 树中任意两个节点之间有且仅有一条简单路径（连通且无环）。
3. 一棵有 $n$ 个节点的树，其度的总和为 $n-1$（因为每个非根节点都有一个父节点指向它）。
4. 树是连通的无环图，也是极小连通图（删除任意一条边则变成非连通图）。

#### 四、树的存储结构

##### 4.1 双亲表示法（Parent Representation）
用数组存储节点，每个节点包含数据域和指向其父节点的下标（或指针）。根节点的父指针为 $-1$。优点：容易找到父节点；缺点：找子节点需遍历整个数组。

##### 4.2 孩子链表表示法（Child Linked List）
为每个节点维护一个链表，存储其所有子节点的地址（或数组索引）。优点：方便查找子节点；缺点：查找父节点需遍历所有链表。

##### 4.3 双亲孩子表示法（Parent-Child）
结合双亲表示法和孩子链表，每个节点同时存储父指针和子节点链表。

##### 4.4 孩子兄弟表示法（Child-Sibling，又称二叉树表示法）
每个节点包含三个域：数据域、指向第一个子节点的指针（firstChild）、指向下一个兄弟节点的指针（nextSibling）。这样可以将任意一棵树转换为二叉树（左子右兄）。这种表示法常用于一般的树结构。

#### 五、森林（Forest）

- **森林**是 $m$（$m \ge 0$）棵互不相交的树的集合。
- 森林与树可互相转换：删除一棵树的根节点，得到森林；为森林添加一个根节点，将每棵树作为其子树，得到一棵树。

#### 六、典型例题

##### 例1：计算树的基本指标
一棵树有 $10$ 个节点，其中度为 $3$ 的节点有 $2$ 个，度为 $2$ 的节点有 $1$ 个，其余为叶子节点，求叶子节点数。
解：设叶子节点数为 $n_0$，则总节点数 $n = n_0 + 2 + 1 = n_0 + 3$。边数 $e = n - 1 = n_0 + 2$。另一方面，边数也等于所有节点的度数之和的一半，即 $\frac{1}{2}(3\times2 + 2\times1 + 0\times n_0) = \frac{1}{2}(6+2)=4$。因此 $n_0 + 2 = 4$，得 $n_0 = 2$。

##### 例2：判断树的高度
一棵树有 $n$ 个节点，采用孩子兄弟表示法存储，问如何求树的高度？
解：树的高度等于根节点到最远叶子节点的路径长度。在左子右兄表示法中，树的高度可以通过递归计算：`height(root) = max( height(firstChild) + 1, height(nextSibling) )`，其中先处理孩子链，兄弟链不增加高度（因兄弟在同一层）。

#### 七、小结

树的基本概念是学习二叉树、二叉搜索树、平衡树、堆、B树等后续结构的基础。你需要掌握：
1. 树的定义及基本术语（根、叶子、父、子、兄弟、祖先、后代、深度、高度、度）。
2. 树的性质（边数、节点数关系，连通性，路径唯一性）。
3. 树的常见存储结构（双亲、孩子链表、孩子兄弟）。
4. 森林与树的转换关系。
5. 能够计算树中的节点数、度数、高度等基本量。

### 2.2 二叉树<a id = "2.2"></a>

二叉树是每个节点最多有两个子树的树结构，是计算机科学中最基础、应用最广泛的数据结构之一。本节系统讲解二叉树的定义、性质、存储、遍历、线索化、应用以及常见变形。

#### 一、二叉树的定义与基本概念

##### 1.1 定义
二叉树（Binary Tree）是 $n$（$n \ge 0$）个节点的有限集合，满足：
- 当 $n = 0$ 时，为空二叉树。
- 当 $n > 0$ 时，有且仅有一个称为**根**的节点；其余节点分成两个互不相交的子集，分别称为**左子树**和**右子树**，且左、右子树本身也是二叉树。

> 注意：二叉树与度为2的树不同。二叉树的子树有左右之分，次序不能颠倒；而度为2的树不区分左右。

##### 1.2 基本术语
- **根节点**：树顶端的节点。
- **叶子节点**：没有子节点的节点。
- **内部节点**：至少有一个子节点的节点。
- **左孩子/右孩子**：节点左/右子树的根。
- **深度**：从根到该节点的路径长度（根深度为0或1，视约定）。
- **高度**：从该节点到最远叶子节点的路径长度。

#### 二、特殊形态的二叉树

| 类型 | 定义 | 示例 |
|------|------|------|
| **满二叉树** | 所有非叶子节点都有两个子节点，且所有叶子节点在同一层 | 深度为 $k$ 的满二叉树有 $2^k-1$ 个节点 |
| **完全二叉树** | 深度为 $k$、有 $n$ 个节点的二叉树，其节点编号与同深度满二叉树的 $1 \sim n$ 号节点一一对应 | 堆结构常用 |
| **斜树** | 所有节点都只有左子（左斜树）或只有右子（右斜树） | 退化为线性表 |
| **正则二叉树** | 每个非叶子节点都有两个子节点（不要求叶子同层） | 也称为严格二叉树 |

#### 三、二叉树的性质

设根节点深度为 $1$（常见教材约定），以下性质成立：

1. **性质1**：第 $i$ 层最多有 $2^{i-1}$ 个节点（$i \ge 1$）。
2. **性质2**：深度为 $k$ 的二叉树最多有 $2^k - 1$ 个节点。
3. **性质3**：对任意二叉树，若叶子节点数为 $n_0$，度为 $2$ 的节点数为 $n_2$，则 $n_0 = n_2 + 1$。
   - 证明：总节点数 $n = n_0 + n_1 + n_2$，分支数 $B = n_1 + 2n_2 = n - 1$，相减即得。
4. **性质4**：具有 $n$ 个节点的完全二叉树深度为 $\lfloor \log_2 n \rfloor + 1$。
5. **性质5**（顺序存储编号规则）：对完全二叉树按从上到下、从左到右编号（根为1），则：
   - 节点 $i$ 的左孩子编号为 $2i$（若 $2i \le n$）；
   - 节点 $i$ 的右孩子编号为 $2i+1$（若 $2i+1 \le n$）；
   - 节点 $i$ 的父节点编号为 $\lfloor i/2 \rfloor$（$i \ge 2$）。

#### 四、二叉树的存储结构

##### 4.1 顺序存储（数组）
利用完全二叉树编号规则，将节点存储在数组中。适用于完全二叉树或满二叉树，对于一般二叉树会造成大量空间浪费（需存放“空”节点）。

**示例**（完全二叉树）：
```
索引： 1 2 3 4 5 6 7
值： A B C D E F G
```
- `tree[1]` 为根，左子 `tree[2]`，右子 `tree[3]`，依此类推。

##### 4.2 链式存储（二叉链表）
每个节点包含数据域和两个指针域（左孩子、右孩子）。这是最常用的存储方式。

```c
typedef struct BiTNode {
    int data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;
```
- n 个节点的二叉链表共有 2n 个指针域，其中有效指针 n−1 个，空指针 n+1 个。
##### 4.3 三叉链表
增加父指针，便于寻找父节点，常用于需要回溯的场景（如AVL树、红黑树）。
```c
typedef struct TriTNode {
    int data;
    struct TriTNode *lchild, *rchild, *parent;
} TriTNode;
```
#### 五、二叉树的遍历

遍历是二叉树最基本的操作，分为深度优先遍历（DFS）和广度优先遍历（BFS）。

##### 5.1 深度优先遍历（递归/非递归）

| 遍历方式 | 访问顺序 | 用途 |
|----------|----------|------|
| **前序遍历** | 根 → 左子树 → 右子树 | 复制二叉树、前缀表达式 |
| **中序遍历** | 左子树 → 根 → 右子树 | 二叉搜索树的有序输出 |
| **后序遍历** | 左子树 → 右子树 → 根 | 计算表达式值、释放二叉树内存 |

**递归实现（以中序为例）**：
```c
void InOrder(BiTree T) {
    if (T != NULL) {
        InOrder(T->lchild);
        printf("%d ", T->data);
        InOrder(T->rchild);
    }
}
```
**非递归实现（利用栈，以中序为例）：**
```c
void InOrderNonRecur(BiTree T) {
    Stack S = InitStack();
    BiTree p = T;
    while (p || !IsEmpty(S)) {
        while (p) {
            Push(S, p);
            p = p->lchild;
        }
        if (!IsEmpty(S)) {
            p = Pop(S);
            printf("%d ", p->data);
            p = p->rchild;
        }
    }
}
```
##### 5.2 广度优先遍历（层序遍历）
按从上到下、从左到右的顺序访问节点，通常使用队列实现。

**算法：**
```c
void LevelOrder(BiTree T) {
    Queue Q;
    EnQueue(Q, T);
    while (!IsEmpty(Q)) {
        BiTree p = DeQueue(Q);
        printf("%d ", p->data);
        if (p->lchild) EnQueue(Q, p->lchild);
        if (p->rchild) EnQueue(Q, p->rchild);
    }
}
```
##### 5.3 由遍历序列重建二叉树
- **已知前序+中序**：前序第一个为根，在中序中找到根，左边为左子树中序，右边为右子树中序；递归构建。
- **已知后序+中序**：后序最后一个为根，类似。
- **已知层序+中序**：也可重建。
- 已知前序+后序无法唯一确定二叉树（除非是满二叉树）。
#### 六、线索二叉树（Threaded Binary Tree）
##### 6.1 产生背景
二叉链表中存在大量空指针（n+1 个），利用这些空指针存储某种遍历顺序下的前驱或后继，可以加快遍历速度并节省空间。
##### 6.2 线索化
- **前驱线索**：左指针指向遍历序列中的前驱节点（若左孩子为空）。
- **后继线索**：右指针指向遍历序列中的后继节点（若右孩子为空）。
- 增设标志位 `ltag` 和 `rtag`：
    - `ltag = 0`：左指针指向左孩子；`ltag = 1`：左指针指向前驱。
    - `rtag` 同理。
##### 6.3 类型
- **前序线索二叉树**：按前序遍历顺序线索化。
- **中序线索二叉树**（最常用）：按中序遍历顺序线索化。
- **后序线索二叉树**。
##### 6.4 遍历线索二叉树
利用线索可在线性时间内完成遍历，无需递归或栈。例如中序线索二叉树的遍历：
```c
BiTNode *FirstNode(BiTNode *p) {
    while (p->ltag == 0) p = p->lchild;
    return p;
}
BiTNode *NextNode(BiTNode *p) {
    if (p->rtag == 1) return p->rchild;
    else return FirstNode(p->rchild);
}
void InOrderThreaded(BiTNode *root) {
    for (BiTNode *p = FirstNode(root); p; p = NextNode(p))
        printf("%d ", p->data);
}
```
#### 七、二叉树的应用

二叉树在计算机科学中有着极其广泛的应用，以下是几个典型场景：

##### 7.1 二叉搜索树（BST）
二叉搜索树是一种特殊的二叉树，满足：左子树所有节点值 < 根节点值 < 右子树所有节点值。支持高效查找、插入、删除操作，平均时间复杂度 $O(\log n)$（平衡时）。它是许多高级数据结构（如AVL树、红黑树）的基础。

##### 7.2 堆（Heap）
堆是一种完全二叉树，通常用数组存储。最大堆中任意节点值 ≥ 其子节点值，最小堆反之。堆是实现优先队列的核心结构，支持 $O(1)$ 获取最值、$O(\log n)$ 插入和删除。常用于堆排序、图的最短路径算法（Dijkstra）等。

##### 7.3 表达式树
表达式树用于存储算术表达式，叶子节点为操作数，内部节点为运算符。后序遍历表达式树可生成后缀表达式（逆波兰式），便于计算；前序遍历生成前缀表达式。表达式树在编译器设计中用于语法分析。

##### 7.4 哈夫曼树（Huffman Tree）
哈夫曼树是最优二叉树，用于数据压缩。通过贪心算法构造，使带权路径长度最小，从而生成不等长编码（哈夫曼编码），实现无损压缩（如ZIP、JPEG中的部分过程）。

##### 7.5 语法树（Syntax Tree）
编译器在解析源代码时会生成抽象语法树（AST），其中每个节点表示一个语法结构（如表达式、语句、函数定义）。后续的语义分析、代码生成都基于AST进行。

##### 7.6 决策树
决策树是机器学习中常用的分类与回归模型。树的内部节点表示特征测试，分支表示测试结果，叶子节点表示类别或数值。决策树具有可解释性强、训练速度快等优点。

##### 7.7 线段树（Segment Tree）
线段树是一种二叉树，用于高效处理区间查询（如区间和、最小值、最大值）和区间更新。它能在 $O(\log n)$ 时间内完成操作，广泛应用于算法竞赛、数据库索引等领域。

##### 7.8 Trie 树（前缀树）
虽然Trie不是二叉树（每个节点可有多个子节点），但其实现常借助二叉树（左子右兄）或数组。Trie用于快速字符串检索、自动补全、拼写检查等。

#### 八、典型例题

##### 例1：已知二叉树前序为 `ABDEGCF`，中序为 `DBGEACF`，求后序。
解：
- 前序第一个 `A` 为根。
- 中序中 `A` 左边 `DBGE` 为左子树中序，右边 `CF` 为右子树中序。
- 前序中 `A` 之后 `B` 为左子树根，`B` 在中序 `DBGE` 中左边 `D` 为左子树，右边 `GE` 为右子树。
- 递归得后序：`DGEBFCA`。

##### 例2：计算完全二叉树叶子节点数
一棵完全二叉树有 $n=100$ 个节点，求叶子节点数。
解：深度 $k = \lfloor \log_2 100 \rfloor + 1 = 6 + 1 = 7$。前6层满节点数 $2^6-1=63$，最后一层节点 $100-63=37$。第6层节点数为 $2^{5}=32$，其中叶子节点数 = 最后一层37个 + 第6层中无孩子的节点数。根据完全二叉树性质，叶子数 = $\lceil n/2 \rceil = 50$。

##### 例3：将二叉树转换为森林
给定一棵二叉树，采用左孩子右兄弟表示法，则左子树为原树的第一棵子树，右子树为原树的下一棵兄弟树。依次分离即可得到森林。

二叉树是树结构的基础，你需要掌握：
1. 二叉树的定义、特殊形态（满、完全、斜）。
2. 五个重要性质及证明。
3. 顺序存储与链式存储的优缺点。
4. 三种深度优先遍历（递归与非递归）和层序遍历。
5. 由遍历序列重建二叉树的方法。
6. 线索二叉树的概念、线索化及遍历。
7. 二叉树在实际问题中的应用（BST、堆、表达式树、哈夫曼树、语法树、决策树、线段树、Trie等）。

### 2.3 二叉搜索树（Binary Search Tree, BST）<a id = "2.3"></a>

二叉搜索树是一种特殊的二叉树，它通过维护节点值之间的有序性，支持高效的动态集合操作（查找、插入、删除）。它是许多平衡树（如AVL树、红黑树）的基础。

#### 一、定义与性质

##### 1.1 定义
二叉搜索树（BST）是一棵二叉树，且满足：
- 对于任意节点 $x$，其左子树中所有节点的值均小于 $x$ 的值。
- 其右子树中所有节点的值均大于 $x$ 的值。
- 左、右子树本身也是二叉搜索树。

> 通常假设树中节点值互异。若允许重复，则可规定左 ≤ 根 ≤ 右或左 < 根 ≤ 右等约定。

##### 1.2 性质
- **中序遍历**：对BST进行中序遍历，得到的节点序列是递增有序的。这是BST最基本的性质。
- **最小值**：从根出发，一直向左走，直到无左孩子，该节点即为最小值节点。
- **最大值**：从根出发，一直向右走，直到无右孩子，该节点即为最大值节点。
- **前驱与后继**：在BST中，一个节点的前驱（中序前驱）是比它小的最大节点；后继是比它大的最小节点。

#### 二、基本操作

##### 2.1 查找（Search）
给定关键字 $k$，从根开始比较：
- 若 $k$ 等于当前节点值，返回该节点。
- 若 $k$ 小于当前节点值，进入左子树继续查找。
- 若 $k$ 大于当前节点值，进入右子树继续查找。
- 若到达空节点，则查找失败。

**时间复杂度**：$O(h)$，其中 $h$ 为树高。

**递归实现**：
```c
BiTree Search(BiTree T, int key) {
    if (T == NULL || T->data == key) return T;
    if (key < T->data) return Search(T->lchild, key);
    else return Search(T->rchild, key);
}
```
**迭代实现：**
```c
BiTree SearchIter(BiTree T, int key) {
    while (T != NULL && T->data != key) {
        if (key < T->data) T = T->lchild;
        else T = T->rchild;
    }
    return T;
}
```
##### 2.2 插入（Insert）
插入一个新节点（假设值不重复）：
1. 若树为空，创建新节点作为根。
2. 否则，从根开始，根据值与当前节点的大小关系，决定向左还是向右递归。
3. 直到找到空位置，将新节点插入。

**时间复杂度**：$O(h)$。

**实现：**
```c
BiTree Insert(BiTree T, int key) {
    if (T == NULL) {
        BiTree newNode = (BiTree)malloc(sizeof(BiTNode));
        newNode->data = key;
        newNode->lchild = newNode->rchild = NULL;
        return newNode;
    }
    if (key < T->data)
        T->lchild = Insert(T->lchild, key);
    else if (key > T->data)
        T->rchild = Insert(T->rchild, key);
    return T;
}
```
##### 2.3 删除（Delete）
删除操作比插入复杂，需考虑三种情况：

**情况1：待删除节点为叶子节点**

直接删除该节点，将其父节点对应的指针置空。

**情况2：待删除节点只有一个子节点**

用其唯一子节点代替该节点。

**情况3：待删除节点有两个子节点**

找到该节点的**中序后继**（或前驱），用后继节点的值覆盖待删除节点，然后递归删除后继节点（后继节点最多只有一个右子节点，转化为情况1或2）。通常选择中序后继（右子树中的最小值节点）。

**时间复杂度**：$O(h)$。

**实现：**
```c
BiTree Delete(BiTree T, int key) {
    if (T == NULL) return NULL;
    if (key < T->data)
        T->lchild = Delete(T->lchild, key);
    else if (key > T->data)
        T->rchild = Delete(T->rchild, key);
    else {
        // 找到待删除节点
        if (T->lchild == NULL) { // 无左孩子或叶子
            BiTree right = T->rchild;
            free(T);
            return right;
        } else if (T->rchild == NULL) { // 无右孩子
            BiTree left = T->lchild;
            free(T);
            return left;
        } else {
            // 有两个孩子：找到中序后继（右子树最小节点）
            BiTree minNode = FindMin(T->rchild);
            T->data = minNode->data;
            T->rchild = Delete(T->rchild, minNode->data);
        }
    }
    return T;
}
```
##### 2.4 查找最值与前驱后继
- **最小值**：一直向左走。
- **最大值**：一直向右走。
- **前驱**：若节点有左子树，则前驱为左子树中的最大值；否则向上找到第一个“父节点是其右孩子”的祖先。
- **后继**：对称。
#### 三、性能分析

BST的操作时间复杂度取决于树的高度 $h$。对于 $n$ 个节点：
- **最好情况**：平衡时 $h = \lceil \log_2 (n+1) \rceil$，查找、插入、删除均为 $O(\log n)$。
- **最坏情况**：当插入序列有序时，BST退化为单链表，$h = n$，操作退化为 $O(n)$。
- **平均情况**：随机插入序列下，BST的平均高度约为 $O(\log n)$，因此平均性能良好。

#### 四、BST的退化与平衡

最坏情况（退化）严重影响了BST的实际应用。为解决此问题，诞生了**平衡二叉搜索树**，如：
- **AVL树**：任何节点左右子树高度差不超过1，通过旋转保持平衡。
- **红黑树**：近似平衡，保证任意节点到叶子的最长路径不超过最短路径的两倍，广泛应用于C++ STL map/set、Java TreeMap等。

平衡树确保所有操作的时间复杂度始终为 $O(\log n)$，适合动态数据集合。

#### 五、应用场景

- **动态查找表**：需要频繁插入、删除和查找的场景。
- **排序**：中序遍历BST即可得到有序序列。
- **范围查询**：BST支持查询区间内的所有元素（结合中序遍历）。
- **作为其他平衡树的基础**（如AVL、红黑树）。
- **字典和集合**：许多编程语言的标准库中的有序容器即基于平衡BST实现。

#### 六、典型例题

##### 例1：给定插入序列，构建BST并计算高度
序列：`5, 3, 7, 2, 4, 6, 8`。构建过程：
- 插入5为根。
- 3 < 5 → 左子。
- 7 > 5 → 右子。
- 2 < 5 → 左子，2 < 3 → 左子。
- 4 < 5 → 左子，4 > 3 → 右子。
- 6 > 5 → 右子，6 < 7 → 左子。
- 8 > 5 → 右子，8 > 7 → 右子。
树高为3（从根到最远叶子路径长度为3），平衡良好。

##### 例2：删除节点
从上述BST中删除3。
- 节点3有左孩子2和右孩子4。找到中序后继：右子树最小节点4。
- 用4覆盖3，然后删除原4（原4为叶子，直接删除）。
结果：5的左子树根变为4，其左孩子2，右孩子NULL。

##### 例3：查找前驱与后继
在原始BST中查找节点4的前驱和后继。
- 前驱：节点4有左子树（2），前驱为左子树中的最大值，即2。
- 后继：节点4的右子树为空，因此向上找第一个“是父节点的左孩子”的祖先。4是父节点3的右孩子，继续向上：3是5的左孩子，所以5是第一个左孩子？实际后继应为5（大于4的最小节点）。符合。

#### 七、BST与有序数组、链表的对比

| 操作 | 有序数组 | 有序链表 | BST（平衡） |
|------|----------|----------|-------------|
| 查找 | $O(\log n)$（二分） | $O(n)$ | $O(\log n)$ |
| 插入 | $O(n)$ | $O(n)$（需遍历） | $O(\log n)$ |
| 删除 | $O(n)$ | $O(n)$ | $O(\log n)$ |
| 有序遍历 | $O(n)$ | $O(n)$ | $O(n)$ |

BST在动态数据集合中综合性能优异。

#### 八、小结

二叉搜索树是学习平衡树的基础。你需要掌握：
1. BST的定义与性质（中序有序性）。
2. 查找、插入、删除操作的实现与时间复杂度分析。
3. 最坏情况（退化）与平衡的重要性。
4. 查找最值、前驱、后继的方法。
5. 能够手工构建BST并执行基本操作。

### 2.4 平衡二叉搜索树（Balanced Binary Search Tree）<a id = "2.4"></a>

二叉搜索树在极端情况下会退化为链表，导致操作效率降低为 $O(n)$。**平衡二叉搜索树**通过约束树的高度，保证插入、删除、查找等操作在最坏情况下仍为 $O(\log n)$。本节介绍两种最常见的平衡树：**AVL树**和**红黑树**。

#### 一、AVL树

##### 1.1 定义
AVL树（Adelson-Velsky and Landis Tree）是**自平衡二叉搜索树**，其平衡条件为：对于任意节点，左子树和右子树的高度差的绝对值不超过1。这个高度差称为**平衡因子**（Balance Factor）：
$$ \text{BF}(node) = \text{height}(node.left) - \text{height}(node.right) $$
AVL树中，BF 只能取 -1, 0, 1。

##### 1.2 基本操作

###### 1.2.1 旋转（Rotation）
当插入或删除破坏平衡时，通过旋转恢复。有四种基本旋转：

| 旋转类型 | 触发条件 | 操作 |
|----------|----------|------|
| **LL旋转**（右单旋） | 插入左子树的左子树导致失衡 | 将根节点的左孩子提升为根，原根变为右孩子 |
| **RR旋转**（左单旋） | 插入右子树的右子树导致失衡 | 将根节点的右孩子提升为根，原根变为左孩子 |
| **LR旋转**（先左后右） | 插入左子树的右子树导致失衡 | 先对左子树左旋，再对根右旋 |
| **RL旋转**（先右后左） | 插入右子树的左子树导致失衡 | 先对右子树右旋，再对根左旋 |

**旋转示例**（LL旋转）：
```
    y (BF=2) x
   / \ /
  x T3 ==> T1 y
 / \ /
T1 T2 T2 T3
```

###### 1.2.2 插入
1. 按BST规则插入新节点。
2. 从插入点向上回溯，更新节点高度。
3. 检查每个祖先的平衡因子，若失衡则进行相应的旋转。
4. 旋转后高度更新，继续向上检查直至根。

时间复杂度 $O(\log n)$。

###### 1.2.3 删除
1. 按BST规则删除节点（同BST删除）。
2. 从被删除节点的父节点开始向上回溯，更新高度并检查平衡。
3. 若失衡则旋转。
4. 可能需要多次旋转。

时间复杂度 $O(\log n)$。

##### 1.3 AVL树的特点
- **严格平衡**：任意节点左右子树高度差 ≤ 1，因此树高严格 $O(\log n)$。
- **查找快**：查找操作与BST相同，但无退化风险。
- **插入/删除开销较大**：可能需要多次旋转，但仍是 $O(\log n)$。
- **应用**：适用于查询多、修改少的场景（如数据库索引中的部分实现）。

#### 二、红黑树（Red-Black Tree）

##### 2.1 定义与性质
红黑树是一种近似平衡的二叉搜索树，通过给节点着色（红或黑）并满足以下5条性质来保证平衡：

1. 每个节点是红色或黑色。
2. 根节点是黑色。
3. 所有叶子（NIL空节点）是黑色。
4. 红色节点的两个子节点必须是黑色（即不能有两个连续的红色节点）。
5. 从任意节点到其每个叶子节点的所有路径都包含相同数目的黑色节点（**黑高**相同）。

这些性质保证了树的最长路径长度不超过最短路径的两倍，从而确保操作 $O(\log n)$。

##### 2.2 基本操作

###### 2.2.1 旋转
与AVL类似，有**左旋**和**右旋**，用于调整结构并保持BST性质。

###### 2.2.2 插入
1. 按BST规则插入新节点，并着为**红色**（除非是根）。
2. 若插入后违反红黑树性质（主要是性质4：红色父节点下有红色子节点），则通过**重新着色**和**旋转**修复。分几种情况（以父节点为祖父的左孩子为例）：
   - **情况1**：叔节点为红色 → 父、叔、祖父变色。
   - **情况2**：叔节点为黑色，且新节点为父的右孩子 → 左旋父节点，转为情况3。
   - **情况3**：叔节点为黑色，且新节点为父的左孩子 → 右旋祖父节点，并重新着色。
3. 最后确保根为黑色。

时间复杂度 $O(\log n)$。

###### 2.2.3 删除
比插入更复杂，也需要通过重新着色和旋转维持性质。删除后若导致黑高不平衡，则进行修复（有多种情况）。时间复杂度 $O(\log n)$。

##### 2.3 红黑树 vs AVL树

| 特性 | AVL树 | 红黑树 |
|------|-------|--------|
| 平衡严格性 | 严格（高度差≤1） | 宽松（最长路径≤2倍最短路径） |
| 树高 | 约 $1.44 \log n$ | 约 $2 \log n$ |
| 查找速度 | 更快（更矮） | 稍慢 |
| 插入/删除旋转次数 | 较多（可能回溯到根） | 较少（平均3次以内） |
| 适用场景 | 查询密集型 | 插入删除频繁（如语言库容器） |

##### 2.4 应用
- **C++ STL**：`std::map`, `std::set` 通常基于红黑树实现。
- **Java**：`TreeMap`, `TreeSet` 使用红黑树。
- **Linux内核**：完全公平调度（CFS）使用红黑树管理进程。
- **数据库**：某些索引结构（如InnoDB的B+树虽不同，但红黑树用于内存排序）。

#### 三、其他平衡树简介

- **替罪羊树（Scapegoat Tree）**：懒散平衡，在插入时检查子树大小是否超过阈值，重建整个子树。实现简单。
- **树堆（Treap）**：结合BST和堆（随机优先级），期望平衡。通过旋转维持堆性质。
- **Splay树**：通过伸展操作将最近访问的节点旋转到根，摊还分析保证 $O(\log n)$。缓存友好，常用于实现自调整序列。

#### 四、典型例题

##### 例1：AVL树插入导致LR旋转
向空AVL树依次插入 3, 2, 1 时，插入1后节点3的BF=2，且插入位置是左子树的右子树？不对：插入3,2,1是LL情况？实际：插入3（根），插入2（3的左孩子），插入1（2的左孩子）。从1向上，节点2 BF=1，节点3 BF=2，且是LL失衡（左孩子的左子树），进行右单旋。最终树为：2为根，左1，右3。

##### 例2：红黑树插入修复
向空红黑树插入10（根，黑色）。插入20（红色，10的右孩子），合法。插入30（红色，20的右孩子）后，20为红色且30红色，违反性质4。此时叔节点（10的左孩子NIL为黑色）为黑色，且30是20的右孩子 → 需先左旋20，再右旋10并重新着色。最终10为红色，20为黑色，30为红色？需具体。

##### 例3：红黑树与AVL树的选用
若系统需要大量查找而很少修改，应选AVL树（如静态字典）。若需要高频插入删除，选红黑树（如进程调度）。

#### 五、小结

平衡二叉搜索树保证了最坏情况下的性能。你需要掌握：
1. AVL树的平衡条件、旋转操作（LL, RR, LR, RL）以及插入删除的平衡恢复过程。
2. 红黑树的5条性质、插入时的修复情况（三种）、删除的基本思想。
3. AVL树与红黑树的区别及各自适用场景。
4. 其他平衡树（替罪羊、Treap、Splay）的简要特点。

### 2.5 B树与B+树<a id = "2.5"></a>

B树和B+树是为磁盘或其他直接存取辅助设备设计的一种平衡多路搜索树。它们通过降低树的高度来减少I/O次数，广泛应用于数据库和文件系统索引。

#### 一、B树（B-Tree）

##### 1.1 定义
一棵 $m$ 阶B树（$m \ge 2$）满足以下性质：
1. 每个节点最多有 $m$ 个子节点（即最多有 $m-1$ 个关键字）。
2. 根节点若不是叶子，则至少有2个子节点；除根外，每个非叶子节点至少有 $\lceil m/2 \rceil$ 个子节点（即至少有 $\lceil m/2 \rceil - 1$ 个关键字）。
3. 所有叶子节点在同一层（即树是完全平衡的）。
4. 节点中的关键字按递增顺序排列，每个关键字将子树分开：设节点有 $k$ 个关键字 $K_1 < K_2 < \dots < K_k$，则其 $k+1$ 个子树 $P_0, P_1, \dots, P_k$ 满足：$P_i$ 中的所有关键字在区间 $(K_i, K_{i+1})$ 内（约定 $K_0 = -\infty$，$K_{k+1}=+\infty$）。

##### 1.2 基本操作

###### 1.2.1 查找
类似二叉搜索树，但在节点内使用顺序查找或二分查找。从根出发，根据关键字选择相应分支，直至找到目标或到达叶子。时间复杂度 $O(\log_m n)$，但由于树高很低，I/O次数很少。

###### 1.2.2 插入
1. 查找插入位置，找到应插入的叶子节点。
2. 若该节点未满（关键字数 < $m-1$），直接插入并保持有序。
3. 若该节点已满，则**分裂**：
   - 将节点中的关键字和待插入关键字排序，取中间位置的关键字 $K_m$ 提升到父节点。
   - 原节点分裂为左右两个节点，分别包含小于和大于 $K_m$ 的关键字。
   - 若父节点也满，则递归向上分裂。若根节点分裂，树高增加1。

###### 1.2.3 删除
删除后可能导致节点关键字数低于下限（$\lceil m/2 \rceil - 1$），需通过**借关键字**或**合并**来调整：
- **借关键字**：若兄弟节点有多余的关键字，则通过父节点旋转借一个。
- **合并**：若兄弟节点也不足，则与兄弟节点及父节点中的分隔关键字合并为一个节点。
- 若根节点被合并后为空，则删除根，树高减1。

##### 1.3 B树的特点
- 每个节点不仅存放索引，还存放数据（或指向数据的指针），常用于文件系统（如NTFS中的B树）。
- 查找、插入、删除操作均保持平衡，所有叶子在同一层。
- 树高很低，例如 $m=100$，$n=10^7$ 时，树高约为 $\log_{100} 10^7 \approx 3.5$，因此I/O次数极少。

#### 二、B+树（B+ Tree）

B+树是B树的一种变体，广泛用于关系数据库索引（如MySQL的InnoDB引擎）。

##### 2.1 与B树的区别
1. **非叶子节点只存储索引**，不存储数据记录（或指向数据的指针）。所有数据记录都存储在叶子节点。
2. **叶子节点之间通过链表连接**（通常是单向或双向链表），便于范围查询和顺序遍历。
3. 非叶子节点的关键字数等于子节点数（即每个关键字对应一个子节点）；而B树中关键字数比子节点数少1。

##### 2.2 结构
- **非叶子节点**：存放若干关键字和指向子节点的指针，关键字用于路由。每个关键字是其右子树中的最小值（或最大值）。
- **叶子节点**：存放数据记录（或指向记录的指针）以及关键字，并按顺序排列。叶子节点之间用指针串联成链表。

##### 2.3 操作

###### 2.3.1 查找
- **单值查找**：从根出发，根据关键字选择分支，最终到达叶子节点，在叶子节点中顺序查找或二分查找目标记录。
- **范围查找**：先找到范围的下界叶子节点，然后通过叶子链表顺序遍历，直到超过上界。

###### 2.3.2 插入
1. 在相应叶子节点中插入记录。若叶子节点未满，直接插入并保持顺序。
2. 若叶子节点满，则分裂：将叶子节点一分为二，并将中间关键字提升到父节点（非叶子节点）。
3. 若父节点也满，则递归分裂。若根节点分裂，树高增加。
4. 维护叶子节点链表。

###### 2.3.3 删除
1. 从叶子节点删除记录。若删除后叶子节点仍满足至少 $\lceil m/2 \rceil$ 个记录，则结束。
2. 若叶子节点下溢，则尝试从兄弟节点借记录，或与兄弟合并。
3. 合并时，需同时调整父节点中的索引关键字，并删除父节点中的对应项。若父节点下溢，则递归处理。

##### 2.4 B+树的优点
- **范围查询高效**：由于叶子链表，范围扫描只需少量I/O。
- **非叶子节点更小**：只存索引，可容纳更多关键字，进一步降低树高。
- **所有查找都经过根到叶子的路径，I/O次数稳定**。
- **数据集中存放在叶子，利于顺序读取**。

##### 2.5 B+树的应用
- **关系数据库索引**（MySQL InnoDB、PostgreSQL等）。
- **文件系统**（如ReiserFS、XFS的部分结构）。
- **操作系统的页缓存管理**。

#### 三、B树与B+树对比

| 特性 | B树 | B+树 |
|------|-----|------|
| 数据存储位置 | 所有节点 | 仅叶子节点 |
| 非叶子节点内容 | 关键字+数据指针 | 仅关键字+子节点指针 |
| 叶子节点是否链表 | 否 | 是 |
| 单值查找 | 可能提前在非叶子结束 | 必须到叶子层 |
| 范围查询 | 需回溯，效率低 | 利用链表，高效 |
| 树高 | 略高（因节点存储数据） | 较低 |
| 典型应用 | 文件系统（如NTFS） | 数据库索引 |

#### 四、典型例题

##### 例1：构造一棵3阶B树
依次插入 10, 20, 30, 40, 50。3阶B树每个节点最多2个关键字（3个孩子），最少1个关键字（2个孩子）。
- 插入10,20：节点[10,20]。
- 插入30：节点满，分裂。取中间关键字20提升为根，左[10]，右[30]。
- 插入40：根右子[30]变为[30,40]。
- 插入50：右子[30,40]满，需分裂。中间关键字40提升到根，根变为[20,40]，右子分裂为[30]和[50]。
最终根[20,40]，左子[10]，中子[30]，右子[50]。

##### 例2：B+树的范围查询优势
在B+树中，若需要查询30到50之间的所有记录，只需找到包含30的叶子节点，然后沿链表遍历直到超过50。在B树中，需多次回溯至父节点，I/O次数多。

#### 五、小结

B树和B+树是专为外存访问优化的数据结构。你需要掌握：
1. B树的定义、阶的概念、节点结构以及插入和删除的分裂、合并过程。
2. B+树与B树的区别：数据仅在叶子、叶子链表、非叶子只存索引。
3. B+树在范围查询和数据库索引中的优势。
4. 能够手工模拟B树/B+树的插入、删除操作。

### 2.6 堆（Heap）<a id = "2.6"></a>

堆是一种特殊的完全二叉树（或基于树结构的优先级队列），它能够高效地获取和删除最值元素，并支持插入操作。堆广泛应用于优先队列、堆排序、图算法（如Dijkstra、Prim）等。本节介绍二叉堆、索引堆、二项堆、斐波那契堆以及左倾堆和斜堆。

#### 一、二叉堆（Binary Heap）

##### 1.1 定义与性质
二叉堆是一种**完全二叉树**，分为**最大堆**和**最小堆**：
- **最大堆**：任意节点的值 ≥ 其子节点的值，根节点为最大值。
- **最小堆**：任意节点的值 ≤ 其子节点的值，根节点为最小值。

由于是完全二叉树，二叉堆通常用**数组**存储。若根节点索引为0（或1），则对于节点 $i$：
- 左子节点索引：$2i+1$（0-index）或 $2i$（1-index）
- 右子节点索引：$2i+2$ 或 $2i+1$
- 父节点索引：$\lfloor (i-1)/2 \rfloor$ 或 $\lfloor i/2 \rfloor$

##### 1.2 基本操作

###### 1.2.1 上滤（Percolate Up / Sift Up）
用于插入操作。将新元素放在数组末尾，然后不断与父节点比较，若违反堆序则交换，直到满足堆序。时间复杂度 $O(\log n)$。

###### 1.2.2 下滤（Percolate Down / Heapify）
用于删除堆顶或建堆。从指定节点开始，与子节点中较大（最大堆）或较小（最小堆）的交换，直到满足堆序。时间复杂度 $O(\log n)$。

###### 1.2.3 插入（Insert）
将新元素插入数组末尾，执行上滤。$O(\log n)$。

###### 1.2.4 删除堆顶（Delete Min/Max）
移除根节点，将数组最后一个元素移到根，然后执行下滤。$O(\log n)$。

###### 1.2.5 建堆（Build Heap）
给定无序数组，从最后一个非叶子节点开始向前依次执行下滤，可在 $O(n)$ 时间内建成堆。

##### 1.3 应用
- **优先队列**：支持 $O(1)$ 取最值，$O(\log n)$ 插入和删除。
- **堆排序**：先建堆，然后反复删除堆顶，得到有序序列，时间复杂度 $O(n \log n)$，空间 $O(1)$。

#### 二、索引堆（Indexed Heap）

##### 2.1 产生背景
普通二叉堆在更新元素值（如减小键值）时，需要知道元素在堆中的位置，若直接修改值后执行上滤/下滤，必须事先找到该元素。索引堆通过维护一个**索引数组**来映射元素位置，支持对任意元素的快速更新和删除。

##### 2.2 结构
索引堆包含三个数组：
- `data`：存储实际元素值（或指针）。
- `index`：堆数组中第 $i$ 个位置对应哪个元素的索引（即从堆位置到元素id的映射）。
- `rev`（反向索引）：元素 $id$ 在堆中的位置（$rev[index[i]] = i$）。

通过反向索引，可以在 $O(1)$ 时间内找到元素的位置，从而执行上滤/下滤。

##### 2.3 基本操作
- **插入**：在 `data` 末尾添加元素，同时在 `index` 末尾记录其id，并维护反向索引，然后上滤。
- **删除堆顶**：交换堆顶与最后一个元素，更新反向索引，然后下滤。
- **更新元素值**：通过反向索引找到位置，修改 `data` 值，然后根据需要上滤或下滤。
- **提取元素**：类似删除堆顶但只提取元素并保持堆结构。

时间复杂度均为 $O(\log n)$。

##### 2.4 应用
- Dijkstra 算法中需要频繁降低节点距离值，使用索引堆可高效更新。
- 动态图算法中需要删除或更新任意优先级的场景。

#### 三、二项堆（Binomial Heap）

##### 3.1 定义
二项堆是由一组**二项树**组成的集合，每个二项树满足最小堆性质，且每个度数（阶）的二项树最多出现一次。二项树 $B_k$ 的递归定义：
- $B_0$ 是单节点树。
- $B_k$ 由两个 $B_{k-1}$ 合并而成，其中一个作为另一个的根的最左孩子。

性质：$B_k$ 有 $2^k$ 个节点，高度为 $k$，根节点有 $k$ 个孩子（分别是从 $B_{k-1}$ 到 $B_0$）。

##### 3.2 操作

###### 3.2.1 合并（Merge）
两个二项堆的合并类似于二进制加法。将两个堆的对应阶的二项树按顺序合并，若同一阶存在两棵树，则合并为一个高阶树（取根较小的作为新根）。时间复杂度 $O(\log n)$。

###### 3.2.2 插入（Insert）
将要插入的元素视为一个 $B_0$ 树，与当前堆合并。时间复杂度 $O(\log n)$。

###### 3.2.3 查找最小值（Find Min）
遍历所有二项树的根，取最小值。由于最多有 $\lfloor \log_2 n \rfloor + 1$ 棵树，时间复杂度 $O(\log n)$，也可维护一个指针优化到 $O(1)$。

###### 3.2.4 删除最小值（Extract Min）
1. 找到最小根所在的树，将其从根链表中移除。
2. 将该树的子节点（它们本身就是一组二项树 $B_{k-1}, B_{k-2}, \dots, B_0$）反转顺序，组成一个新的二项堆。
3. 将原剩余堆与新堆合并。时间复杂度 $O(\log n)$。

###### 3.2.5 减小键值（Decrease Key）
找到节点，减小其值，然后不断与父节点比较并交换（类似于二叉堆的上滤），直到满足堆序。由于二项树中每个节点有父指针，操作 $O(\log n)$。

###### 3.2.6 删除（Delete）
通过减小键值为负无穷，然后删除最小值。$O(\log n)$。

##### 3.3 优点与缺点
- **优点**：合并操作非常高效（$O(\log n)$），优于二叉堆的 $O(n)$（若将两个堆合并需逐个插入）。
- **缺点**：实现复杂，查找最小值需要遍历根链表。

#### 四、斐波那契堆（Fibonacci Heap）

##### 4.1 定义与结构
斐波那契堆是对二项堆的改进，通过**懒标记**和**级联剪枝**，使得某些操作（尤其是减小键值）摊还代价极低。它由一组**最小堆序**的树组成，树根之间形成循环双向链表。

每个节点包含：
- 父节点指针、子节点指针（循环双向链表）。
- 度数（孩子数）。
- 标记（是否失去过孩子）。

##### 4.2 操作摊还分析
- **插入**：创建一个新树（单节点），加入根链表。摊还 $O(1)$。
- **查找最小值**：维护一个最小指针，$O(1)$。
- **合并**：将两个根链表连接，$O(1)$。
- **删除最小值（Extract Min）**：
  1. 移除最小节点，将其子节点加入根链表。
  2. 反复合并度数相同的树（类似二项堆），直至每个度数至多一棵树。摊还 $O(\log n)$（实际均摊）。
- **减小键值**：
  1. 将节点值减小，若不破坏堆序则结束。
  2. 否则，将该节点切离父节点，移到根链表，并设置其父节点的标记。
  3. 若父节点已标记（之前失去过孩子），则继续级联切离。摊还 $O(1)$。
- **删除**：减小键值为 $-\infty$，再删除最小值。摊还 $O(\log n)$。

##### 4.3 优点与缺点
- **优点**：减小键值的摊还 $O(1)$，使得Dijkstra算法（需要频繁降低距离）的理论复杂度从 $O((V+E)\log V)$ 降到 $O(V \log V + E)$。
- **缺点**：常数大，实现复杂，实际性能未必优于二叉堆（尤其是小规模数据）。

#### 五、左倾堆（Leftist Heap）与斜堆（Skew Heap）

##### 5.1 左倾堆

###### 5.1.1 定义
左倾堆是一种可合并堆（mergeable heap），基于二叉树（不一定是完全二叉树），满足**堆序**和**左倾性质**：
- **堆序**：任意节点的值 ≤ 其子节点的值（最小堆）。
- **左倾性质**：对每个节点，定义 **null path length (NPL)** 为该节点到最近空节点的距离（空节点NPL=0）。左倾堆要求：左子节点的NPL ≥ 右子节点的NPL，即右子树更“倾斜”。这保证了合并操作的高效。

###### 5.1.2 合并操作（核心）
左倾堆的合并是递归的：
- 若一个堆为空，返回另一个。
- 比较两个堆的根，取较小根作为新根。
- 将其右子树与另一个堆合并，然后交换左右子树（若右子树NPL > 左子树NPL）。最终使左倾性质满足。

时间复杂度 $O(\log n)$。

###### 5.1.3 其他操作
- **插入**：将新节点视为单节点堆，与原堆合并。$O(\log n)$。
- **删除最小值**：删除根，然后合并左右子树。$O(\log n)$。

##### 5.2 斜堆（Skew Heap）

###### 5.2.1 定义
斜堆是左倾堆的简化版，它不维护NPL信息，而是在每次合并后无条件交换左右子树（即始终使右子树变短）。这样也能保证摊还 $O(\log n)$ 的复杂度。

###### 5.2.2 合并操作
与左倾堆类似，但无需维护NPL，合并后始终交换左右子树。实现更简单。

###### 5.2.3 摊还分析
斜堆的合并操作摊还复杂度为 $O(\log n)$，实际性能通常不错。

#### 六、各种堆的比较

| 堆类型 | 插入 | 取最小值 | 删除最小值 | 合并 | 减小键值 | 适用场景 |
|--------|------|----------|------------|------|----------|----------|
| 二叉堆 | $O(\log n)$ | $O(1)$ | $O(\log n)$ | $O(n)$ | $O(\log n)$ | 通用优先队列，堆排序 |
| 索引堆 | $O(\log n)$ | $O(1)$ | $O(\log n)$ | - | $O(\log n)$ | Dijkstra算法等需要更新元素 |
| 二项堆 | $O(\log n)$ | $O(\log n)$ (可优化到$O(1)$) | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ | 需要高效合并的场合 |
| 斐波那契堆 | $O(1)$ 摊还 | $O(1)$ | $O(\log n)$ 摊还 | $O(1)$ | $O(1)$ 摊还 | 理论最优，但常数大 |
| 左倾堆/斜堆 | $O(\log n)$ | $O(1)$ | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ | 可合并堆，斜堆实现简单 |

#### 七、典型例题

##### 例1：二叉堆建堆
给定数组 `[5,3,8,2,6,1,9,7]` 构造最小堆。
从最后一个非叶子节点（索引3，值为2）开始下滤：
- 索引3（值2）：无子节点，不变。
- 索引2（值8）：与子节点1和9比较，选较小1交换，得 `[5,3,1,2,6,8,9,7]`。
- 索引1（值3）：与子节点2和6比较，选2交换，得 `[5,2,1,3,6,8,9,7]`。
- 索引0（值5）：与子节点2和1比较，选1交换，得 `[1,2,5,3,6,8,9,7]`，再对5下滤（与3,8比较，3交换）得 `[1,2,3,5,6,8,9,7]`。最终堆：`[1,2,3,5,6,8,9,7]`。

##### 例2：二项堆合并
两个二项堆分别有 $B_0$（单节点2）和 $B_1$（根1，孩子3）和另一个堆有 $B_0$（4），$B_1$（根0，孩子5）。合并过程略。

#### 八、小结

堆是优先级队列的核心实现。你需要掌握：

2. 索引堆的结构（`index` 和 `rev` 数组）及其在Dijkstra算法中的应用。
3. 二项堆的树结构、合并过程（二进制加法）及各种操作。

5. 左倾堆的NPL定义、合并操作及斜堆的简化。

### 2.7 字典树（Trie）<a id = "2.7"></a>

字典树（Trie，又称前缀树）是一种用于高效存储和检索字符串集合的数据结构。它利用字符串的公共前缀来减少查询时间，支持插入、查找、前缀匹配等操作，时间复杂度与字符串长度相关，而与集合大小无关。本节介绍标准Trie、压缩Trie（Patricia Trie）、后缀树与后缀数组，以及典型应用。

#### 一、标准Trie（Standard Trie）

##### 1.1 定义与结构
Trie是一棵多叉树，每个节点代表一个字符（从根到某节点的路径对应一个字符串）。根节点不存储字符，每个节点包含：
- 一个数组（或哈希表）存储子节点指针（通常有26个字母大小）。
- 一个布尔标志（或计数器）表示该节点是否为一个单词的结尾。

例如，插入单词 `"cat"`, `"car"`, `"dog"` 后，Trie结构如下：
```
root
/
c d
/ \
a a o
/ \
t r g
(end) (end) (end)
```

##### 1.2 基本操作

###### 1.2.1 插入（Insert）
从根开始，依次遍历单词的每个字符：
- 若当前节点的子节点中不存在该字符，则创建新节点。
- 移动到子节点。
- 处理完所有字符后，标记该节点为单词结尾。

时间复杂度 $O(L)$，其中 $L$ 为字符串长度。

###### 1.2.2 查找（Search）
类似插入，沿着字符路径走，若路径存在且最后节点被标记为单词结尾，则查找成功；否则失败。$O(L)$。

###### 1.2.3 前缀匹配（StartsWith/KeysWithPrefix）
查找是否存在以给定前缀开头的单词。只需走完前缀路径，然后遍历其子树所有单词结尾节点。$O(L + M)$，其中 $M$ 为匹配的单词个数。

###### 1.2.4 删除（Delete）
递归删除：先找到单词结尾节点，将其标记取消；然后若该节点无子节点且不是其他单词的结尾，则向上删除。需注意不能删除其他单词共享的节点。

##### 1.3 优缺点
- **优点**：查找和插入时间只与单词长度有关，与集合大小无关；支持前缀查询。
- **缺点**：空间消耗大（每个节点可能包含大量空指针）。可改用哈希表（如 `unordered_map`）或压缩路径来优化。

#### 二、压缩Trie（Patricia Trie）

##### 2.1 产生背景
标准Trie中，许多单分支节点（只有一个子节点）造成空间浪费。压缩Trie将单分支节点合并到其父节点，用字符串片段（边标签）代替单个字符。

##### 2.2 结构
- 每个边标签是一个字符串（可能多个字符）。
- 内部节点至少有两个子节点（除非是叶子）。
- 查找时，一次比较整个字符串片段。

##### 2.3 操作
- **插入**：先沿路径比较，若出现不匹配，则分裂节点。
- **查找**：逐段比较，直到完全匹配或失败。

空间效率显著提升，适用于大量长字符串存储。

#### 三、后缀树（Suffix Tree）与后缀数组（Suffix Array）

##### 3.1 后缀树
后缀树是字符串所有后缀构成的压缩Trie。例如字符串 `"banana"` 的所有后缀：`"banana"`, `"anana"`, `"nana"`, `"ana"`, `"na"`, `"a"`。将所有这些后缀插入压缩Trie，得到后缀树。

**性质**：
- 每个叶子对应一个后缀（起始位置）。
- 内部节点表示子串，且至少有2个子节点。
- 构建时间 $O(n)$（使用Ukkonen算法），空间 $O(n)$。

**应用**：
- 快速查找子串（是否存在，出现次数，位置等）。
- 最长重复子串、最长公共子串等。

##### 3.2 后缀数组
后缀数组是字符串所有后缀按字典序排序后的起始索引数组，常配合LCP（最长公共前缀）数组使用。例如 `"banana"` 的后缀排序后索引为 `[5,3,1,0,4,2]`（对应后缀："a","ana","anana","banana","na","nana"）。

**构建**：
- 朴素 $O(n^2 \log n)$，倍增算法 $O(n \log n)$，DC3算法 $O(n)$。

**应用**：
- 子串搜索（二分查找后缀数组）。
- 计算LCP数组可求解最长重复子串等。

后缀树与后缀数组可互相转换，各有优缺点：后缀树空间较大但查询更快；后缀数组空间更小，但需配合LCP和二分查找。

#### 四、应用

##### 4.1 自动补全（Autocomplete）
Trie支持前缀搜索，输入前缀后，可遍历子树返回所有以该前缀开头的单词，常用于搜索引擎输入框、IDE代码补全等。

##### 4.2 拼写检查（Spell Checker）
将词典存入Trie，快速判断单词是否存在；对错误单词，可基于编辑距离或其他算法查找最接近的正确词。

##### 4.3 IP路由（IP Routing）
路由器中，IP前缀匹配（最长前缀匹配）可用Trie（或比特Trie）实现。每个节点对应一个二进制位，路径对应IP地址前缀，叶子节点或内部节点存储下一跳信息。

##### 4.4 其他
- **单词统计**：在Trie节点上记录计数器，统计单词出现频率。
- **文本索引**：后缀树/后缀数组用于全文搜索、模式匹配。

#### 五、典型例题

##### 例1：实现Trie的插入和查找
```python
class TrieNode:
    def __init__(self):
        self.children = [None]*26
        self.is_end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str):
        node = self.root
        for ch in word:
            idx = ord(ch)-ord('a')
            if not node.children[idx]:
                node.children[idx] = TrieNode()
            node = node.children[idx]
        node.is_end = True

    def search(self, word: str) -> bool:
        node = self.root
        for ch in word:
            idx = ord(ch)-ord('a')
            if not node.children[idx]:
                return False
            node = node.children[idx]
        return node.is_end
```
##### 例2：求字符串最长公共前缀
给定字符串数组，构建Trie，然后从根开始，若有且只有一个分支，则继续向下，直到分叉或单词结束，此时路径即为最长公共前缀。或者直接纵向比较。

##### 例3：使用后缀数组查找子串
字符串 `s = "banana"`，后缀数组 `sa = [5,3,1,0,4,2]`。查找子串 `"ana"`：在后缀数组中二分查找，找到起始索引为3（后缀 `"ana"`）和1（后缀 `"anana"`），即可得到所有出现位置（3,1）。

#### 六、小结
字典树及其变种是处理字符串集合的利器。你需要掌握：
1. 标准Trie的结构（节点、子节点数组、单词结束标记）及插入、查找、删除、前缀匹配操作。
2. 压缩Trie（Patricia Trie）如何合并单分支节点，节省空间。
3. 后缀树（所有后缀的压缩Trie）和后缀数组（排序后缀索引）的基本概念及典型应用（子串搜索、最长重复子串）。
4. 自动补全、拼写检查、IP路由等实际应用场景。

### 2.8 线段树与树状数组<a id = "2.8"></a>

线段树和树状数组（Fenwick Tree）是两类用于处理区间查询和单点更新的数据结构。它们能够在 $O(\log n)$ 时间内完成区间统计（如求和、最值、最大公约数等）以及单点修改，广泛应用于算法竞赛、数据库索引、区间问题求解等场景。本节分别介绍线段树和树状数组的原理、操作、实现及应用。

#### 一、线段树（Segment Tree）

##### 1.1 定义与结构
线段树是一棵平衡二叉树，每个节点代表一个区间 $[L, R]$，并存储该区间的聚合信息（如区间和、最小值、最大值等）。叶子节点对应单个元素。

- 根节点代表整个数组区间 $[0, n-1]$。
- 对于节点代表区间 $[L, R]$，若 $L = R$，则为叶子；否则，取中点 $M = \lfloor (L+R)/2 \rfloor$，左孩子代表 $[L, M]$，右孩子代表 $[M+1, R]$。

线段树通常用数组存储：根节点下标为1，左孩子为 $2i$，右孩子为 $2i+1$。数组大小一般开 $4n$ 以保证安全。

##### 1.2 基本操作

###### 1.2.1 建树（Build）
递归或迭代构建：叶子节点存储原数组值；内部节点根据左右孩子信息合并（如求和、取最值）。时间复杂度 $O(n)$。

**示例（区间求和）**：
```c++
int a[N]; // 原数组
int tree[4*N];

void build(int node, int l, int r) {
    if (l == r) {
        tree[node] = a[l];
        return;
    }
    int mid = (l + r) / 2;
    build(node*2, l, mid);
    build(node*2+1, mid+1, r);
    tree[node] = tree[node*2] + tree[node*2+1];
}
```
###### 1.2.2 单点更新（Update）
递归找到对应叶子，更新其值，然后向上更新祖先节点的聚合信息。时间复杂度 $O(\log n)$。
```cpp
void update(int node, int l, int r, int idx, int val) {
    if (l == r) {
        tree[node] = val;
        return;
    }
    int mid = (l + r) / 2;
    if (idx <= mid) update(node*2, l, mid, idx, val);
    else update(node*2+1, mid+1, r, idx, val);
    tree[node] = tree[node*2] + tree[node*2+1];
}
```
###### 1.2.3 区间查询（Query）
递归查询区间 $[ql,qr]$ 的聚合信息。若当前节点区间完全被覆盖，直接返回；若部分重叠，递归左右孩子并合并结果。时间复杂度 $O(\log n)$。
```cpp
int query(int node, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return tree[node];
    int mid = (l + r) / 2, res = 0;
    if (ql <= mid) res += query(node*2, l, mid, ql, qr);
    if (qr > mid) res += query(node*2+1, mid+1, r, ql, qr);
    return res;
}
```
##### 1.3 区间更新与懒标记（Lazy Propagation）
当需要将区间 $[L,R]$ 内所有元素加上某个值（或赋值为某个值）时，若每次单点更新，复杂度 $O(n \log n)$ 不可接受。懒标记技术通过在节点上记录“未下传的更新”，在查询或进一步更新时才将标记下推，将区间更新也降至 $O(\log n)$。

**懒标记示例（区间加，区间求和）：**
```cpp
int lazy[4*N];

void push(int node, int l, int r) {
    if (lazy[node] != 0) {
        tree[node] += lazy[node] * (r - l + 1);
        if (l != r) {
            lazy[node*2] += lazy[node];
            lazy[node*2+1] += lazy[node];
        }
        lazy[node] = 0;
    }
}

void update_range(int node, int l, int r, int ul, int ur, int val) {
    push(node, l, r);
    if (ul <= l && r <= ur) {
        lazy[node] += val;
        push(node, l, r);
        return;
    }
    int mid = (l + r) / 2;
    if (ul <= mid) update_range(node*2, l, mid, ul, ur, val);
    if (ur > mid) update_range(node*2+1, mid+1, r, ul, ur, val);
    tree[node] = tree[node*2] + tree[node*2+1];
}
```
##### 1.4 可持久化线段树（Persistent Segment Tree）

可持久化线段树支持访问历史版本。每次修改时，新建一条路径上的节点，复用未修改的子节点。常用于查询区间第 $k$ 小数、可持久化数组等。

**原理**：每次更新从根到叶子的路径上创建新节点，旧节点保留。时间复杂度 $O(\log n)$，空间复杂度 $O(m \log n)$，其中 $m$ 为更新次数。

#### 二、树状数组（Fenwick Tree / Binary Indexed Tree）

##### 2.1 定义与结构
树状数组是一种基于数组的、支持单点更新和前缀查询的数据结构，通常用于求和、异或等可逆运算。其核心思想是利用二进制分解，将前缀和分解为若干区间和。

设原始数组为 $a[1..n]$，树状数组 $c[1..n]$ 定义为：
$$ c[i] = \sum_{j = i - \text{lowbit}(i) + 1}^{i} a[j] $$
其中 $\text{lowbit}(i) = i \& (-i)$，表示 $i$ 的二进制最低位1所对应的值。

##### 2.2 基本操作

###### 2.2.1 单点更新（Add）
将位置 $i$ 增加 $val$，需要更新所有包含 $i$ 的树状数组位置：$i, i+\text{lowbit}(i), i+2\cdot\text{lowbit}(i), \dots$，直到 $n$。

```c++
void add(int i, int val) {
    while (i <= n) {
        c[i] += val;
        i += i & -i;
    }
}
```
时间复杂度 $O(\log n)$。
###### 2.2.2 前缀查询（Sum）
求 $[1,i]$ 的和：累加 $c[i],c[i−lowbit(i)],c[i−lowbit(i)−lowbit(i−lowbit(i))],…$。
```cpp
int sum(int i) {
    int res = 0;
    while (i > 0) {
        res += c[i];
        i -= i & -i;
    }
    return res;
}
```
###### 2.2.3 区间查询
利用前缀和相减得到 $[l,r]$ 的和：$sum(r)−sum(l−1)$。
##### 2.3 初始化
两种方法：
- 对每个位置执行 $n$ 次 `add(i, a[i])`，$O(n \log n)$。
- 利用前缀和直接构建：先计算前缀和 $pre[i]$，然后 $c[i] = pre[i] - pre[i - \text{lowbit}(i)]$，$O(n)$。

##### 2.4 树状数组的扩展
- **区间更新、单点查询**：利用差分思想，维护差分数组 $d[i] = a[i] - a[i-1]$，则区间 $[l, r]$ 加 $val$ 对应 `add(l, val)` 和 `add(r+1, -val)`，单点查询即为前缀和。
- **区间更新、区间查询**：需要维护两个树状数组，分别记录 $d[i]$ 和 $i \cdot d[i]$，推导出区间和公式。
- **求逆序对**：离散化后，遍历数组，每次查询已出现的大于当前元素的个数（即 `sum(n) - sum(x)`），然后 `add(x, 1)`。

##### 2.5 线段树 vs 树状数组

| 特性 | 线段树 | 树状数组 |
|------|--------|----------|
| 代码复杂度 | 较高 | 很低 |
| 空间 | $4n$ | $n$ |
| 操作类型 | 区间和、最值、GCD、区间加/赋值等 | 主要支持可逆运算（和、异或），可通过差分扩展 |
| 区间更新 | 支持（懒标记） | 需差分技巧，且只能处理特定类型 |
| 可持久化 | 支持 | 较难 |
| 通用性 | 强 | 弱（仅适用于特定运算） |

通常情况下，若仅需前缀和或单点更新、区间查询，树状数组更加轻量；若需要复杂区间操作（如区间最值、区间赋值），则使用线段树。

#### 三、典型例题

##### 例1：线段树求区间最大值
给定数组，支持单点修改和区间最大值查询。只需将建树、更新、查询中的合并操作改为 `max` 即可。

##### 例2：树状数组求逆序对
给定数组 `[3, 1, 2]`，离散化后为 `[2, 1, 2]`（实际值映射到排名）。遍历：
- i=1: 查询前缀和 `sum(2)` 得0，逆序对+0；`add(2,1)`。
- i=2: `sum(1)` 得0，逆序对+0；`add(1,1)`。
- i=3: `sum(2)` 得 `c[2]=1, c[1]=1`，`sum(2)=2`；逆序对 = 当前已出现的大于当前元素的个数 = `i-1 - sum(x)` = `2 - 2 = 0`？实际逆序对为 (3,1) 一个。正确计算方法：每次 `add(x,1)` 后，当前元素产生的逆序对数为 `i - sum(x)`，其中 `sum(x)` 是 ≤ x 的元素个数。对于 `x=2`，`i=3`，`sum(2)=2`，逆序对为 `3-2=1`。最终逆序对数 = 1。

##### 例3：区间加、区间求和的线段树实现
使用懒标记，详细见前文代码。

#### 四、小结

线段树和树状数组是处理区间问题的两大利器。你需要掌握：

1. 线段树的数组表示、建树、单点/区间更新（懒标记）、区间查询。
2. 可持久化线段树的基本思想。
3. 树状数组的定义（利用 lowbit），单点更新和前缀查询。
4. 树状数组的扩展应用：区间更新+单点查询（差分），区间更新+区间查询（两个BIT），求逆序对。
5. 能够根据问题特点选择合适的结构（线段树通用但较复杂，树状数组轻量但受限）。

### 2.9 并查集与笛卡尔树<a id = "2.9"></a>

本节介绍两种重要的树形数据结构：**并查集**（Disjoint Set Union）和**笛卡尔树**（Cartesian Tree）。它们分别用于管理不相交集合的合并与查询，以及基于序列构建满足堆序的二叉树，在算法竞赛和工程实践中具有广泛应用。

#### 一、并查集（Disjoint Set Union, DSU）

并查集是一种管理元素分组（不相交集合）的数据结构，支持高效地合并两个集合以及查询两个元素是否属于同一集合。常用于图论中的连通分量、最小生成树（Kruskal 算法）、动态连通性等问题。

##### 1.1 基本概念
- 每个集合用一棵树表示，树根为该集合的**代表元**。
- 支持两种操作：
  - **查找（Find）**：确定元素所在集合的代表元。
  - **合并（Union）**：将两个不同的集合合并为一个。

##### 1.2 数组表示
- `parent[x]`：元素 $x$ 的父节点，根节点的父节点指向自身。
- 可选数组 `size[x]` 或 `rank[x]`，用于按秩合并优化。

##### 1.3 查找（Find）与路径压缩
```c++
int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]); // 路径压缩
    return parent[x];
}
```
路径压缩使查找的均摊复杂度接近常数。

##### 1.4 合并（Union）与按秩合并
```cpp
void unite(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return;
    // 按秩合并（将小树挂到大树下）
    if (rank[rx] < rank[ry])
        parent[rx] = ry;
    else if (rank[rx] > rank[ry])
        parent[ry] = rx;
    else {
        parent[ry] = rx;
        rank[rx]++;
    }
}
```
按秩合并保证树高 $O(\log n)$，与路径压缩结合后，单次操作的均摊复杂度为 $O(α(n))$（反阿克曼函数，近乎常数）。
##### 1.5 应用场景
- **图论**：判断无向图连通分量、检测环（Kruskal 算法）。
- **动态连通性**：在线添加边，查询两点是否连通。
- **等价关系**：维护等价类（如朋友关系、同余类）。
- **扩展**：
  - **带权并查集**：维护节点到根的距离（向量、模运算）。
  - **可持久化并查集**：支持历史版本查询。

##### 1.6 典型例题
**冗余连接（LeetCode 684）**：给定一个无向图，删除一条边使其成为树。使用并查集，依次加入边，若某条边连接的两个端点已连通，则该边为冗余边。

#### 二、笛卡尔树（Cartesian Tree）

笛卡尔树是一种特殊的二叉树，由给定序列构建，满足：
- **堆性质**：每个节点的值（优先级）满足最小堆（或最大堆）性质，即根最小。
- **中序遍历**：中序遍历笛卡尔树得到原序列的顺序。

笛卡尔树可在线性时间内构建，常用于 RMQ（区间最值查询）、后缀数组等。

##### 2.1 定义
对于序列 $A[1..n]$，笛卡尔树的每个节点对应一个元素，满足：
1. **堆序**：父亲节点的值小于（或大于）子节点的值（本文以最小堆为例）。
2. **中序**：中序遍历得到原序列的下标顺序。

##### 2.2 线性时间构建
使用栈维护右链（根到最右叶子的路径）。算法步骤：
1. 新建节点 `node` 对应 `A[i]`。
2. 从栈顶开始弹出，直到栈空或栈顶节点的值小于 `A[i]`。
3. 将最后一个弹出的节点作为 `node` 的左孩子。
4. 如果栈非空，将 `node` 作为栈顶节点的右孩子。
5. 将 `node` 压入栈。

时间复杂度 $O(n)$。

**C++ 示例**（最小堆）：
```c++
vector<int> parent(n+1, 0);
stack<int> stk;
for (int i = 1; i <= n; ++i) {
    int last = 0;
    while (!stk.empty() && A[stk.top()] > A[i]) {
        last = stk.top();
        stk.pop();
    }
    if (!stk.empty()) parent[i] = stk.top();
    if (last) parent[last] = i;
    stk.push(i);
}
```
##### 2.3 性质与应用
- **与 RMQ 的关系**：在最小堆笛卡尔树中，区间 $[l,r]$ 的最小值位置等于节点 $l$ 和 $r$ 的最近公共祖先（LCA）。利用这一性质可 $O(1)$ 查询 RMQ（需预处理 LCA）。
- **应用场景**：
    - 区间最值查询（RMQ）辅助结构。
    - 后缀数组的构造辅助（如后缀自动机）。
    - Treap：随机优先级下的笛卡尔树。
    - 序列分割：按最小值将序列分成左右子树，递归处理。
##### 2.4 典型例题
构建笛卡尔树并输出每个节点的父节点：给定序列 `[3, 2, 5, 1, 4]`，构建最小堆笛卡尔树。过程略，最终根为 1，树结构可画出。
#### 三、小结
- **并查集** 是处理动态连通性和等价类的高效结构，核心优化为路径压缩与按秩合并，单次操作均摊复杂度几乎为常数。
- **笛卡尔树** 是结合堆序与中序遍历的二叉树，可线性构建，在 RMQ 和序列分割问题中有重要应用。
